# M4 plan: the public records and the asynchronous API

- **Date:** 2026-10-26
- **Status:** draft. A point citing ADR-0021 to ADR-0024 was decided by the maintainer. The
  rest is this plan's design, which a slice's measurements and review may revise. Each slice
  starts with the measurements it lists.
- **Scope:** brief §8's M4, and what the records hand M4 (the M3 plan, §8)
- **Records:** [ADR-0009](decisions/0009-typed-escape-hatch.md) ·
  [ADR-0012](decisions/0012-engine-thread-owns-every-handle.md) (amended 2026-10-26) ·

  [ADR-0021](decisions/0021-completions-through-a-mailbox.md) (new) ·
  [ADR-0022](decisions/0022-codes-classed-as-condition-types.md) (new) ·

  [global-constraints](global-constraints.md)

M4 makes the low level public. Until now `(curl)` exports what it loaded, the base condition, and
the refusal and wrong-thread conditions.
After M4 a caller can:

- make a request, a body among its fields;
- submit it to an engine, and await its token, or have its callback run from a mailbox;
- catch what failed by class;
- attach an option chez-curl does not wrap, through `(curl unsupported)`.

- **M4 adds no policy** (brief §6.1). Redirect and retry policy, sessions and the thread sugar
  are M5's. The request's defaults are libcurl's own.
- **The engine's design does not change.** M4 adds one act to it, appending a finished token to
  a mailbox (ADR-0021), and exports it.
- **M4 has four slices:** the request, then the asynchronous API, then the environment, then the
  hatch.

## 2. Measured before planning (2026-10-26)

- **The codes.** The floor's `include/curl/curl.h` names `CURLcode`s 0 to 99. 8.23.0's adds
  100, `CURLE_TOO_LARGE`, and 101, `CURLE_ECH_REQUIRED`, and renames 34 and 41 obsolete. Both
  lists were read from the builds' headers.
- **A failure's code moves with the version.** `test-transfer`'s rows already show it:

  | Scenario | 7.85.0 | 8.5.0 | 8.7.1 | 8.20.0 | 8.23.0 |
  |---|---|---|---|---|---|
  | an oversized response head | 27 | 27 | 100 | 100 | 100 |
  | 100,000 headers | 200 | 56 | 56 | 100 | 100 |

  A proxy that refuses a CONNECT gives 56 on 7.85.0 and 8.5.0, and 7 on 8.20.0 and 8.23.0
  (below). So a class can only follow the code (ADR-0022).
- **The proxy variables** ([`research/m4/proxy/`](research/m4/proxy/)). A C probe made one
  transfer under `env -i`, with only the variables each case named. A stand-in proxy answered
  299 and logged each request it got. On 7.85.0, Ubuntu's 8.5.0 with OpenSSL and with GnuTLS,
  Guix's 8.20.0 and 8.23.0, each alike:
  - `http_proxy`, `all_proxy`, `ALL_PROXY`, `https_proxy` and `HTTPS_PROXY` each sent the
    transfer through the proxy, which logged it;
  - a lone `HTTP_PROXY` was ignored;
  - `no_proxy` and `NO_PROXY` naming the host sent it direct;
  - `CURLOPT_PROXY` `""` and `CURLOPT_NOPROXY` `"*"` each sent it direct, with the proxy
    logging nothing.
- **The TLS variables and `pkcs11:`** were measured for ADR-0018, on the four Linux libcurls.
  ADR-0024 cites them.

## 3. Decisions that bind every slice

### 3.1 The public surface

- **`(curl)` exports, by the end of M4:**
  - the request: `make-curl-request`, `curl-request-with`, `curl-request?` and an accessor per
    key (§3.2);
  - the response: its predicate and accessors, its timings among them (§3.3);
  - the engine: `make-curl-engine`, `curl-engine?` and `curl-engine-stop`;
  - submitting: `curl-submit`, with an optional mailbox and callback (§3.5);
  - the token: `curl-token?`, `curl-token-await`, `curl-token-wait`, `curl-token-cancel` and
    `curl-token-done?`;
  - the mailbox: `make-curl-mailbox`, `curl-mailbox?`, `curl-mailbox-take` and
    `curl-mailbox-deliver`;
  - every condition a caller can meet: `&curl-url-error`, `&curl-request-error`,
    `&curl-transfer-error` with its classes (§3.4), and `&curl-engine-error`.
    `&curl-embedded-nul` is defined and raised nowhere in `src/`, so slice 1 deletes it or
    exports it, by what a caller can meet.
- **What stays private:** the chunk log, planted faults, the engines made without
  `QUICK_EXIT`, the live and queued counts, and everything native. Each private test seam is
  reached only from `(curl private ...)`.
- **Every export carries a Typed Racket style signature** (AGENTS.md), and `(curl)` names each
  condition's reasons.

### 3.2 The request (ADR-0023)

- **`(make-curl-request URL KEY VALUE ...)`** with these keys, each once at most:

  | Key | Value | Default | Options it sets |
  |---|---|---|---|
  | `method` | `get`, `head`, `post`, `put`, `patch` or `delete` | `get` | `NOBODY`, or the body's |
  | `headers` | a list of name and value pairs, Latin-1 | none | `HTTPHEADER` |
  | `body` | a bytevector, or `#f` | `#f` | the body's (below) |
  | `user-agent` | a Latin-1 string, or `#f` | `#f` | `USERAGENT` |
  | `timeout-ms` | a positive long, or `#f` | `#f` | `TIMEOUT_MS` |
  | `connect-timeout-ms` | a positive long, or `#f` | `#f` | `CONNECTTIMEOUT_MS` |
  | `body-limit` | a natural below 2^63 - 1, or `#f` | `#f` | `MAXFILESIZE_LARGE` |
  | `ca-file` | a path, or `#f` for libcurl's system store | `#f` | `CAINFO`, `CAPATH` |
  | `verify` | a boolean | `#t` | `SSL_VERIFYPEER`, `SSL_VERIFYHOST` |
  | `proxy` | `environment`, or `#f` (slice 3) | `environment` | `PROXY` |

  `#f` leaves libcurl's own default. The request still holds no procedure.
- **Refused, by name, before anything else is checked:** an unknown key, a repeated key, and a
  key with no value. These are `&curl-request-error`s, with reasons of their own.
- **A body goes with `post`, `put`, `patch` or `delete`,** and is refused with `get` or `head`.
  `post` with no body sends an empty one.
- **The body is copied twice:** into the submit's private copy, and by libcurl from foreign
  memory when the transfer is set up. The design, which slice 1 measures first:
  - `POSTFIELDSIZE_LARGE` with the length, then `COPYPOSTFIELDS` with a counted block, freed
    once setopt returns;
  - `put`, `patch` and `delete` set `CUSTOMREQUEST` to the method's name, beside the body.
- **libcurl still owns the framing:** `Content-Length` and `Transfer-Encoding` stay refused.
  libcurl may add a `Content-Type` and an `Expect` of its own to a body. Slice 1 records what each
  libcurl sends, byte for byte, and then decides whether the request suppresses them. The
  plan's proposal: the request sends only the headers it names, so libcurl's own are
  suppressed with an empty header of each name, unless the request names one.
- **Owned options gain** the body's, `PROXY` and `CONNECTTIMEOUT_MS`. Their twins are refused by
  the seam and the hatch (ADR-0009): among them `POSTFIELDS`, `POSTFIELDSIZE`, `POST`, `HTTPPOST`,
  `MIMEPOST`, `UPLOAD`, `PUT`, `INFILESIZE` and `INFILESIZE_LARGE`, `CONNECTTIMEOUT`,
  `NOPROXY` and `PRE_PROXY`. Slice 1 reads the options table for every other twin, and the
  review checks the list.

### 3.3 Timeouts, and the response's timings

- **A request has two timeouts:** the whole transfer, `timeout-ms`, and the connection phase,
  `connect-timeout-ms`. Neither has a default: libcurl's own stand, as the low level has no
  policy.
- **A wait has a bound of its own:** `curl-token-wait TOKEN MS` answers whether the token is done
  within MS, and leaves it running either way. `curl-mailbox-take` takes a bound too. Await
  itself stays unbounded, as in M3.
- **The response gains its timings,** read with `curl_easy_getinfo` as `curl_off_t`
  microseconds when the transfer finishes: the name lookup, the connect, the TLS handshake, the
  first byte and the total. Each is held as data, as the rest of the response is. Brief §6.2
  puts timing in the response.

### 3.4 The classes (ADR-0022)

- **Each class is a condition type under `&curl-transfer-error`,** made with every base field,
  with a predicate `(curl)` exports. A code with no class raises the base type.
- **The first proposal for the table,** which slice 1 settles by curl's description of each code
  and by measuring each a scenario can reach:

  | Class | Codes |
  |---|---|
  | `&curl-timeout` | 28 |
  | `&curl-connect-error` | 5, 6, 7, 45, 96, 97 |
  | `&curl-connection-lost` | 52, 55, 56 |
  | `&curl-tls-error` | 35, 53, 54, 58, 59, 60, 64, 66, 77, 80, 82, 83, 90, 91, 98, 101 |
  | `&curl-protocol-error` | 1, 3, 8, 16, 18, 61, 92, 95 |
  | `&curl-too-large` | 63, 100, and the reason `body-limit` |
  | `&curl-too-many-redirects` | 47 |

  Every other code from 0 to 101 has no class. 1 is here because the transfer is pinned to
  `http` and `https`, so libcurl answers it for a reply that is no HTTP, and for a redirect to
  another scheme. 3 is here because submit checks the caller's URL first, so libcurl answers it
  for a redirect's `Location`. Slice 1 measures both.
- **The suite writes out every row, 0 to 101,** and a test holds the library's table to it. A
  mutant moving one code fails it, by that code.
- **The version rows stay codes.** A row's class follows from its code through the table, and
  `test-transfer` asserts both.

### 3.5 Submitting, awaiting and the mailbox (ADR-0021)

- **`(curl-submit ENGINE REQUEST [MAILBOX [CALLBACK]])`** takes the private copy, checks it on the
  caller's thread, and queues it, as the engine's submit does now. A callback needs a mailbox.
- **The completing thread appends the token to its mailbox,** under the mailbox's mutex, inside
  the critical section it already completes the token in. The engine's mutex is taken first,
  and the mailbox's never waits.
- **`(curl-mailbox-take MAILBOX MS)`** answers the next finished token, or `#f` once MS has
  passed. Its wait polls, as await's does (ADR-0013, amended 2026-10-25).
- **`(curl-mailbox-deliver MAILBOX MS)`** takes as take does, calls the token's callback with the
  token on the calling thread, and answers what the callback answered, or `#f` if no token came.
  The callback's raise leaves through it.
- **A token without a callback is delivered by `take` alone.** A callback without a mailbox is
  refused at submit.
- **The test ADR-0012 asks for, its delivery half:** each callback records its thread, and the
  suite asserts it is the delivering thread, never the engine's. A mutant that calls the
  callback where the token completes must fail it, by name. A cancel's completion, on a
  caller's thread, is checked too.

### 3.6 The environment (ADR-0024)

- **The `proxy` field:** `environment`, the default, sets nothing, and libcurl reads the
  variables. `#f` sets `PROXY` to `""`. A test runs a child with `http_proxy` at a stand-in
  proxy, and judges each by the proxy's log: the default reaches it, `#f` does not.
- **Guix's override:**
  - native reads `SSL_CERT_FILE` and `SSL_CERT_DIR` immediately before `curl_global_init`, and
    records what it read;
  - a table by world and version, in `src/`, says which libcurls override: Guix's 8.20.0 does,
    its 8.6.0 does not, and a Guix libcurl with no row is taken to;
  - submit refuses a request with a CA file there, with either recorded set, as
    `&curl-request-error`, naming the variable;
  - `test-transfer-tls`'s pin keeps its own table, and holds the library's to it.
- **`pkcs11:`:** a CA path beginning so, in any ASCII case, is refused when the request is made.
- **README.org** names `SSLKEYLOGFILE` and `OPENSSL_CONF`, with what was measured.

### 3.7 The hatch (ADR-0009)

- **`(curl unsupported)` exports one procedure,** which takes a request and a list of name and
  value pairs, and answers a new request carrying them. Each is checked as it is attached:
  - the name is known to the loaded libcurl;
  - its type is long, enumerated values, `off_t`, string, blob or string list;
  - its value fits the type;
  - no string holds NUL, CR or LF;
  - it is neither owned nor an owned setting's twin, by id.
- **The engine applies them last,** after the request's own and the pins.
- **Lifetimes:** a blob is passed through `struct curl_blob` with `CURL_BLOB_COPY`; a string list
  is built by the binding, counted as `slist`, and freed with the transfer.
- **The test seam, `curl-engine-submit-with`, retires into the hatch,** which holds its rules and
  more. For each check that used the seam, slice 4 says what would make it fail now (`traps.md`,
  on deletion).

### 3.8 The seam's and the conventions' reviewed additions

- **check-seam:** `(curl unsupported)` is a `(curl ...)` library no `(http-client ...)` library
  may import (ADR-0009, decision 1). No new Chez name is planned: `getenv` is already allowed.
- **foreign-conventions:** no new entry point is planned. The body and the blob go through the
  pointer setopt binding, and the timings through the getinfo one.
- **test-constants:** `struct curl_blob`, `CURL_BLOB_COPY` and the new `CURLINFO`s, each with a
  row. Each must exist in the floor's headers, or carry its gate. The class table is by number,
  so it needs no constant for 100 and 101, which the floor's headers lack.

## 4. Slice 1: the request, its body, and the classes

### 4.1 First, measure

On the four Linux libcurls, and 8.23.0, each through a C probe against the test origin:
- **What a body sends:** each method with a body of 0, 1, 1,024, 1,025 and 1 MiB + 1 bytes,
  by `COPYPOSTFIELDS` and by `CUSTOMREQUEST`, read by the byte probe: the request line, every
  header libcurl adds (`Content-Type`, `Expect`), and the body's bytes.
- **What suppresses libcurl's own headers,** on each libcurl.
- **What the connection phase covers:** whether `CONNECTTIMEOUT_MS` ends a TLS handshake the
  server never answers, and how a suite can stall a connect on loopback.
- **Each code a scenario can reach,** for the class table: a redirect to another scheme, a
  malformed `Location`, too many redirects, and the timeouts.
- **The timings,** whether each is set, and in order, on each libcurl.

### 4.2 What it builds

- §3.1's request and response exports, §3.2, §3.3 but the waits, and §3.4.
- **`test-request`:** the keys, their refusals and defaults, each method with and without a
  body, the body's bytes as the origin received them, and the body copied: a bytevector changed
  after submit sends what submit took.
- **`test-transfer`'s rows** gain each scenario's class.

## 5. Slice 2: the asynchronous API

### 5.1 First, measure

- **Whether a process-directed SIGINT can land on the engine's thread,** on Linux and the Mac,
  with the main thread waiting in a take. The engine is public now, so a dropped Ctrl-C reaches
  callers (carried from M3 slice 1).
- **A take's delay** from completion to delivery, idle and under the gate's Valgrind.

### 5.2 What it builds

- §3.1's engine, token and mailbox exports, §3.3's waits, and §3.5.
- **`test-mailbox`:** many tokens from two engines into one mailbox, each delivered once;
  take's bound; a callback's raise; a cancel's completion delivered; stop's `stopped` tokens
  delivered; the delivery test; and counts at zero.

## 6. Slice 3: the environment (ADR-0024)

### 6.1 First, measure

- **When Guix's patch reads the variables:** whether one set after the load changes a transfer
  on Guix's 8.20.0, and whether an empty value counts as set.
- **Which spellings GnuTLS takes as PKCS#11:** `pkcs11:` and other cases, on 8.20.0 and Ubuntu's
  8.5.0.

### 6.2 What it builds

§3.6, with a check for each refusal watched firing, and the proxy child judged by the proxy's
own log.

## 7. Slice 4: the hatch (ADR-0009)

### 7.1 First, measure

- **The options table,** on each libcurl: which names each type covers, and every owned
  setting's twin.
- **A blob and a string list through the hatch,** each freed once, under the gate's Valgrind.

### 7.2 What it builds

§3.7, with `test-unsupported`: each refusal rule watched firing, an alias of an owned option,
CR, LF and NUL in a string and a list, a blob and a list each reaching libcurl, and counts at
zero.
