# M4 plan: the public records and the asynchronous API

- **Date:** 2026-10-26
- **Status:** draft, merged in PR #23, then revised on 2026-10-26 after an adversarial review
  of the plan: each record it touched carries an amendment, "after the plan's review". A point
  citing ADR-0021 to ADR-0024 was decided by the maintainer. The rest is this plan's design,
  which a slice's measurements and review may revise. Each slice starts with the measurements
  it lists.
- **Scope:** brief §8's M4, and what the records hand M4 (the M3 plan, §8)
- **Records:** [ADR-0009](decisions/0009-typed-escape-hatch.md) ·
  [ADR-0012](decisions/0012-engine-thread-owns-every-handle.md) (amended 2026-10-26) ·
  [ADR-0018](decisions/0018-ca-file-is-the-only-anchor.md) (amended 2026-10-26) ·
  [ADR-0021](decisions/0021-completions-through-a-mailbox.md) (new) ·

  [global-constraints](global-constraints.md)

M4 makes the low level public. Until now `(curl)` exports what it loaded, the base condition, and
the refusal and wrong-thread conditions.
After M4 a caller can:

- make a request, a body among its fields;
- submit it to an engine, and await its token, or have its callback run from a mailbox;
- catch what failed by class;
- attach an option chez-curl does not wrap, through `(curl unsupported)`.

- **M4 adds no policy** (brief §6.1). Redirect and retry policy, sessions and the thread sugar
  are M5's. The request's defaults are libcurl's own.
- **The engine's design does not change.** M4 adds one act to it, appending a finished token to
  a mailbox (ADR-0021), and exports it.
- **M4 has four slices:** the request, then the asynchronous API, then the environment, then the
  hatch.

## 2. Measured before planning (2026-10-26)

- **The codes.** The floor's `include/curl/curl.h` names `CURLcode`s 0 to 99. 8.23.0's adds
  100, `CURLE_TOO_LARGE`, and 101, `CURLE_ECH_REQUIRED`, and renames 34 and 41 obsolete. Both
  lists were read from the builds' headers.
- **A failure's code moves with the version.** `test-transfer`'s rows already show it:

  | Scenario | 7.85.0 | 8.5.0 | 8.7.1 | 8.20.0 | 8.23.0 |
  |---|---|---|---|---|---|
  | an oversized response head | 27 | 27 | 100 | 100 | 100 |
  | 100,000 headers | 200 | 56 | 56 | 100 | 100 |

  A proxy that refuses a CONNECT gives 56 on 7.85.0 and 8.5.0, and 7 on 8.20.0 and 8.23.0
  (below). So a class can only follow the code (ADR-0022).
- **The proxy variables** ([`research/m4/proxy/`](research/m4/proxy/)). A C probe made one
  transfer under `env -i`, with only the variables each case named. A stand-in proxy answered
  299 and logged each request it got. On 7.85.0, Ubuntu's 8.5.0 with OpenSSL and with GnuTLS,
  Guix's 8.20.0 and 8.23.0, each alike:
  - `http_proxy`, `all_proxy`, `ALL_PROXY`, `https_proxy` and `HTTPS_PROXY` each sent the
    transfer through the proxy, which logged it;
  - a lone `HTTP_PROXY` was ignored;
  - `no_proxy` and `NO_PROXY` naming the host sent it direct;
  - `CURLOPT_PROXY` `""` sent it direct with `http_proxy`, `all_proxy` or `https_proxy` set,
    and `CURLOPT_NOPROXY` `"*"` with `http_proxy` or `https_proxy`: the proxy logged nothing.
    That each holds for the other variables is libcurl's source (`lib/url.c`), not this
    measurement.
- **Bodies and redirects,** measured by the plan's review
  ([`research/m4/redirect/`](research/m4/redirect/)): a C probe against a Node server that
  echoes what it got, on 7.85.0, Ubuntu's 8.5.0 with OpenSSL, Guix's 8.20.0 and 8.23.0, each
  alike, and rerun in the container:
  - libcurl adds `Content-Type: application/x-www-form-urlencoded` to a body on every method,
    `PUT`, `PATCH` and `DELETE` by `CUSTOMREQUEST` as well as `POST`;
  - with `FOLLOWLOCATION`, a 301, 302 or 303 turns a `POST` into a `GET` without its body, and
    resends a `CUSTOMREQUEST` method with no body. A 303 should become a `GET`, and a `PUT`
    through a 301 or 302 should keep its body. 307 and 308 keep the method and the body.
    libcurl documents the custom method's part, and `CURLFOLLOW_OBEYCODE`, which changes it,
    arrived in 8.13.0, above the floor;
  - an empty body passed to `COPYPOSTFIELDS` as NULL and as `""` sent the same request,
    `Content-Length: 0`; a `PUT` with no body sent no `Content-Length`;
  - libcurl's `Expect: 100-continue` threshold is 1 MiB, `EXPECT_100_THRESHOLD` in the
    `lib/http.h` of 7.85.0 and 8.20.0.
- **The TLS variables and `pkcs11:`** were measured for ADR-0018, on the four Linux libcurls.
  ADR-0024 cites them.

## 3. Decisions that bind every slice

### 3.1 The public surface

- **`(curl)` exports, by the end of M4:**
  - the request: `make-curl-request`, `curl-request-with`, `curl-request?` and an accessor per
    key (§3.2);
  - the response: its predicate and accessors, its timings among them (§3.3);
  - the engine: `make-curl-engine`, `curl-engine?` and `curl-engine-stop`;
  - submitting: `curl-submit`, with an optional mailbox and callback (§3.5);
  - the token: `curl-token?`, `curl-token-await`, `curl-token-wait`, `curl-token-cancel` and
    `curl-token-done?`;
  - the mailbox: `make-curl-mailbox`, `curl-mailbox?`, `curl-mailbox-take` and
    `curl-mailbox-deliver`;
  - every condition a caller can meet: `&curl-url-error`, `&curl-request-error`,
    `&curl-transfer-error` with its classes (§3.4), `&curl-engine-error`, and
    `&curl-embedded-nul`, which native's backstop, `refuse-nul`, raises for a string holding
    U+0000 that reaches it unchecked.
- **What stays private:** the chunk log, planted faults, the engines made without
  `QUICK_EXIT`, the live and queued counts, and everything native. Each private test seam is
  reached only from `(curl private ...)`.
- **Every export carries a Typed Racket style signature** (AGENTS.md), and `(curl)` names each
  condition's reasons.

### 3.2 The request (ADR-0023)

- **`(make-curl-request URL KEY VALUE ...)`** with these keys, each once at most:

  | Key | Value | Default | Options it sets |
  |---|---|---|---|
  | `method` | `get`, `head`, `post`, `put`, `patch` or `delete` | `get` | `NOBODY` for `head`; `CUSTOMREQUEST` for `put`, `patch` and `delete`; with the body's for a body |
  | `headers` | a list of name and value pairs, Latin-1 | none | `HTTPHEADER` |
  | `body` | a bytevector, or `#f` | `#f` | the body's (below) |
  | `user-agent` | a Latin-1 string, or `#f` | `#f` | `USERAGENT` |
  | `timeout-ms` | a positive long, or `#f` | `#f` | `TIMEOUT_MS` |
  | `connect-timeout-ms` | a positive long, or `#f` | `#f` | `CONNECTTIMEOUT_MS` |
  | `body-limit` | a natural below 2^63 - 1, or `#f` | `#f` | `MAXFILESIZE_LARGE` |
  | `ca-file` | a path, or `#f` for libcurl's system store | `#f` | `CAINFO`, `CAPATH` |
  | `verify` | a boolean | `#t` | `SSL_VERIFYPEER`, `SSL_VERIFYHOST` |
  | `proxy` | `environment`, or `#f` (slice 3) | `environment` | `PROXY` |

  `#f` leaves libcurl's own default. The request still holds no procedure.
- **Refused, by name, before anything else is checked:** an unknown key, a repeated key, and a
  key with no value. These are `&curl-request-error`s, with reasons of their own, proposed as
  `unknown-key`, `repeated-key` and `missing-value`.
- **A body goes with `post`, `put`, `patch` or `delete`.** With `get` or `head` it is refused,
  as `&curl-request-error`, reason `body-not-allowed`.
- **With no body, `post`, `put` and `patch` send an empty one,** `Content-Length: 0`: a `PUT`
  with no body sent no `Content-Length` (§2), and RFC 9110 asks a `PUT` or `PATCH` to frame its
  content. A `delete` with no body sends none.
- **The body is copied three times:** into the submit's private copy, which lives with the
  transfer, into a counted block, and by libcurl from that block when the transfer is set up
  (corrected after slice 1's review):
  - `POSTFIELDSIZE_LARGE` with the length, then `COPYPOSTFIELDS` with a counted block, freed
    once setopt returns. An empty body passes a block of one byte, never NULL (revised in
    slice 1), as a defence: with a size of 0 libcurl reads nothing either way, but NULL tells
    it to send the body through its read callback, whose default reads stdin, and with a size
    of 0 its setopt allocates a byte "to mark that postfields is used rather than read
    function" (`lib/setopt.c`, 7.85.0). NULL and `""` sent the same request
    (§2), so nothing on the wire tells the two apart;
  - `put`, `patch` and `delete` set `CUSTOMREQUEST` to the method's name.
- **libcurl still owns the framing:** `Content-Length` and `Transfer-Encoding` stay refused.
  libcurl adds `Content-Type: application/x-www-form-urlencoded` to every method's body (§2),
  and adds `Expect: 100-continue` to one over 1 MiB, then waits a second for a server that
  never answers it. So a request that sends a body also sends `Content-Type:` and `Expect:`,
  which take libcurl's own away, unless it names a header of that name, which replaces
  libcurl's, in any case. Slice 1 measured it on five libcurls (§4.1). `Accept: */*` and `Host`
  stay libcurl's, as since M2.
- **`FOLLOWLOCATION` is owned, and left off.** Through a 301, 302 or 303, libcurl resends a
  `CUSTOMREQUEST` method without its body, on every libcurl measured (§2), and the option that
  changes it is above the floor. So nothing in M4 follows a redirect, and M5 follows them
  itself, from `CURLINFO_REDIRECT_URL`. The redirect-pin tests that set it through the test
  seam keep a private way, built in slice 1: a private `follow` field, set by
  `curl-request-following`, which `(curl)` does not export.
- **Owned options gain** the body's, `CUSTOMREQUEST`, `FOLLOWLOCATION`, `PROXY`,
  `CONNECTTIMEOUT_MS`, and every `PROXY_SSL_*` and `PROXY_CA*` option, which keep a proxy's
  TLS at libcurl's verified default until M7 (ADR-0024, amended). Their twins are refused by the
  seam and the hatch (ADR-0009): among them `POSTFIELDS`, `POSTFIELDSIZE`, `POST`, `HTTPPOST`,
  `MIMEPOST`, `UPLOAD`, `PUT`, `INFILESIZE` and `INFILESIZE_LARGE`, `CONNECTTIMEOUT`,
  `NOPROXY` and `PRE_PROXY`. As built in slice 1, from the options tables of five libcurls
  (§4.1): the URL's twins `PORT`, a long the test seam took until then, and `REQUEST_TARGET`;
  `CRLF` and `HEADER`, longs too, found by the slice's review;
  and all 23 `PROXY_` TLS options, the `PROXY_SSL_*` and `PROXY_CA*` ones and the rest, which
  could loosen a proxy's TLS too: its version, ciphers and TLS-SRP among them. `PROXY`,
  `NOPROXY` and `PRE_PROXY` come with slice 3's field.
- **The twin review covers every type the hatch takes,** strings, lists and blobs too, which
  the seam's type rule hid. Among them: `REQUEST_TARGET`, which rewrites the request line;
  `UNIX_SOCKET_PATH`, which also bypasses every proxy; and `COOKIEFILE` at `"-"`, which makes
  libcurl read stdin on the engine's thread. Slice 1 reads the options table on each libcurl
  for the list, and the slice's review checks it.

### 3.3 Timeouts, and the response's timings

- **A request has two timeouts:** the whole transfer, `timeout-ms`, and the connection phase,
  `connect-timeout-ms`. Neither has a default: libcurl's own stand, as the low level has no
  policy. The connect timeout's test has a control: a transfer past its connect phase that
  outlives the bound must succeed, or a mutant sending it as `TIMEOUT_MS` passes. As built,
  `/raw/pause-mid-body?ms=1000` under a connect timeout of 300 ms: `/raw/stall-after-head`,
  the review's proposal, never succeeds, since it stalls for good.
- **A wait has a bound of its own:** `curl-token-wait TOKEN MS` answers whether the token is done
  within MS, and leaves it running either way. `curl-mailbox-take` takes a bound too. Await
  itself stays unbounded, as in M3.
- **The response gains its timings,** read with `curl_easy_getinfo` as `curl_off_t`
  microseconds when the transfer finishes: the name lookup, the connect, the TLS handshake, the
  first byte and the total. Each is held as data, as the rest of the response is. Brief §6.2
  puts timing in the response.
- **A failed transfer's condition carries its request size,** `CURLINFO_REQUEST_SIZE`, the bytes
  of request libcurl sent, 0 when it sent none, so M5's retry policy can tell whether a request
  was sent: a class alone cannot (§3.4). Its timings could not: on a failure they move with the
  version, and 8.23.0 fills pretransfer for a connect that was refused (slice 1's measurement;
  ADR-0022, amended 2026-10-26, decided by the maintainer).
- **They are read through an `off_t` reader,** never the `long` one, which is right only on
  LP64, and tested on scenarios whose phases are far apart, so a mutant reading one `CURLINFO`
  for all five fails.

### 3.4 The classes (ADR-0022)

- **Each class is a condition type under `&curl-transfer-error`,** made with every base field,
  with a predicate `(curl)` exports. A code with no class raises the base type.
- **The first proposal for the table,** revised after the plan's review (ADR-0022, amended),
  which slice 1 settles by curl's description of each code and by measuring each a scenario can
  reach:

  | Class | Codes | In curl's words |
  |---|---|---|
  | `&curl-timeout` | 28 | the operation timed out |
  | `&curl-connect-error` | 5, 6, 7, 45, 96, 97 | the proxy or host could not be resolved, the connection could not be made, or the proxy's handshake failed |
  | `&curl-send-receive-error` | 18, 52, 55, 56 | sending or receiving failed, nothing came back, or the transfer was shorter or longer than declared |
  | `&curl-tls-error` | 35, 53, 54, 58, 59, 60, 64, 66, 77, 80, 82, 83, 90, 91, 98, 101 | the TLS handshake, the peer's certificate, or the local TLS material |
  | `&curl-protocol-error` | 1, 8, 16, 61, 92, 95 | the reply was no HTTP the transfer could read |
  | `&curl-too-large` | 63, 100 | a size limit was passed |

  Every other code from 0 to 101 has no class, and neither has a code past 101.
- **A class names what libcurl answered, never the cause.** The suite's table lists the
  scenarios that reach each code:
  - 56 is what libcurl answers for a bad chunk size, for 100,000 headers on 8.5.0 and 8.7.1,
    and for a refused CONNECT on 7.85.0 and 8.5.0, none of them a lost connection;
  - a body cut short is 18 after a clean close and 56 after a reset, from the same bytes, so 18
    sits with 56;
  - a connect error includes a proxy variable that names no proxy that answers, 5 or 7.

  So M5's retry policy cannot read "retryable" from a class alone, and a failure carries its
  request size (§3.3).
- **Nothing in M4 follows a redirect** (§3.2), so libcurl never answers 47, nor 3, which it
  gives only while following, nor 1 for a redirect to another scheme. 47 and 3 have no class,
  and the redirects class is dropped: M5 raises its own. 1 stays a protocol error, for a reply
  that is no HTTP.
- **Which reasons are classed:** the class follows the code for `perform-failed` alone.
  `body-limit` is `&curl-too-large`, whatever its code, 23. Every other reason raises the base
  type, `callback-raised` and a `setopt-failed` whose code a class names among them. The suite
  writes the rule out, and each class's constructor refuses a reason it does not take.
- **Every classed code is a named constant in `(curl private constants)`,** checked against the
  headers, as every constant is (global-constraints). 100, `CURLE_TOO_LARGE`, carries its gate,
  8.6.0, and 101, `CURLE_ECH_REQUIRED`, 8.8.0, as `CURLMOPT_QUICK_EXIT` does. The library's
  table is keyed by those names.
- **The suite writes out every row, 0 to 101,** and a test holds the library's table to it,
  with 102 and 999 raising the base type. A mutant moving one code fails it, by that code.
- **The version rows stay codes.** `test-transfer` derives each answer's class through the
  suite's own table, and asserts the raised type is that class.

### 3.5 Submitting, awaiting and the mailbox (ADR-0021)

- **`(curl-submit ENGINE REQUEST [MAILBOX [CALLBACK]])`** takes the private copy, checks it on the
  caller's thread, and queues it, as the engine's submit does now. A callback needs a mailbox.
- **The completing thread appends the token to its mailbox,** under the mailbox's mutex, inside
  the critical section it already completes the token in. The engine's mutex is taken first,
  and the mailbox's never waits.
- **`(curl-mailbox-take MAILBOX MS)`** answers the next finished token, or `#f` once MS has
  passed. Its wait polls, as await's does (ADR-0013, amended 2026-10-25).
- **`(curl-mailbox-deliver MAILBOX MS)`** takes as take does, and calls the token's callback,
  if it has one, with the token on the calling thread. It answers the token, or `#f` once MS
  has passed, never the callback's value, so a callback answering `#f` is no timeout. A token
  with no callback is handed over the same way, calling nothing. The callback's raise leaves
  through it. Take never runs a callback.
- **A callback without a mailbox is refused at submit.**
- **A take that escapes loses a notice, never an outcome** (ADR-0021, amended). The take
  removes the token inside a critical section, and leaving one runs a pending interrupt at once
  (ADR-0012, amended 2026-10-24). So a handler that escapes there, or between deliver's take
  and its callback, leaves a token out of the mailbox that no caller holds, and its callback
  unrun. Its outcome stays on the token, which stays done, as await's does. So the mailbox
  carries notices, and the token keeps the outcome: a caller whose interrupt handlers can
  escape keeps its tokens and awaits them. M5's request group does, since it must cancel what
  it leaves. A test plants an escaping interrupt at the take, as `tests/engine-interrupt.sps`
  plants them in await, and then awaits the token's outcome.
- **The test ADR-0012 asks for, its delivery half:** each callback records its thread, and the
  suite asserts it is the delivering thread, never the engine's. A mutant that calls the
  callback where the token completes must fail it, by name. A cancel's completion, on a
  caller's thread, is checked from a thread other than the delivering one, or that mutant
  passes there.

### 3.6 The environment (ADR-0024)

- **The `proxy` field:** `environment`, the default, sets nothing, and libcurl reads the
  variables. `#f` sets `PROXY` to `""`. A test runs a child with `http_proxy` at a stand-in
  proxy, and with `no_proxy` and `NO_PROXY` cleared, and judges each by the proxy's log: the
  default reaches it, `#f` does not.
- **A proxy's TLS stays libcurl's verified default,** against its system store, until M7
  (ADR-0024, amended, decided by the maintainer). The request's `ca-file` and `verify` do not
  reach it, and every `PROXY_SSL_*` and `PROXY_CA*` option is owned, so the hatch cannot loosen
  it. Guix's patch writes the proxy's CA from `SSL_CERT_FILE` too: the operator's setting,
  recorded.
- **Guix's override:**
  - native reads `SSL_CERT_FILE` and `SSL_CERT_DIR` immediately before `curl_global_init`,
    which is when Guix's patch reads them (its source), and records what it read. An empty
    value counts as unset, as libcurl's `curl_getenv` reads it;
  - a table in `src/` says which libcurls override, keyed by whether the loaded library's
    resolved path is under `/gnu/store`, and by its version. A Guix libcurl loaded through
    `CHEZ_CURL_LIBCURL` by a Chez outside Guix is still Guix's, which libc's world would miss.
    Guix's 8.20.0 overrides, and every other Guix libcurl is taken to: 8.6.0's measurement was
    not kept, and `test-transfer-tls` records it as unrecorded;
  - submit refuses a request with a CA file and verification on there, with either recorded
    set, as `&curl-request-error`, naming the variable. With verification off, libcurl reads no
    CA, so nothing is refused (ADR-0018, decision 3);
  - `test-transfer-tls`'s pin keeps its own table, and holds the library's to it.
- **`pkcs11:`:** a CA path beginning so, in any ASCII case, is refused when the request is made.
  The test tries each of the prefix's seven characters in both cases, near misses, and a
  non-ASCII fold, U+212A KELVIN SIGN for `k`, which must pass: Chez's `string-ci=?` folds
  Unicode, and GnuTLS compares bytes.
- **README.org** names `SSLKEYLOGFILE`, `OPENSSL_CONF` and `CURL_SSL_BACKEND`, with what was
  measured. On Apple's MultiSSL libcurl, `CURL_SSL_BACKEND` selects the backend, and its
  LibreSSL falls back to the keychain when a CA file fails (`traps.md`). The Mac measures
  whether that undoes a CA file; if it does, what to do is the maintainer's.

### 3.7 The hatch (ADR-0009)

- **`(curl unsupported)` exports one procedure,** which takes a request and a list of name and
  value pairs, and answers a new request carrying them. Each value is copied as it is attached,
  the copy is checked, and the copy is what the engine applies: the caller's strings and lists
  are never read again (global-constraints). A test flips a hatch string and a hatch list from
  another thread, as `test-transfer` does for headers. An unknown or repeated name is refused at
  attach, as `&curl-request-error`, and `curl-request-with` keeps the options attached. Each
  value is checked:
  - the name is known to the loaded libcurl;
  - its type is long, enumerated values, `off_t`, string, blob or string list;
  - its value fits the type;
  - no string holds NUL, CR or LF;
  - it is neither owned nor an owned setting's twin, by id.
- **The engine applies them last,** after the request's own and the pins.
- **Lifetimes:** a blob is passed through `struct curl_blob` with `CURL_BLOB_COPY`; a string list
  is built by the binding, counted as `slist`, and freed with the transfer.
- **The test seam, `curl-engine-submit-with`, retires into the hatch,** which holds its rules and
  more. For each check that used the seam, slice 4 says what would make it fail now (`traps.md`,
  on deletion). ADR-0009 and global-constraints are amended when it goes.
- **`test-unsupported` writes out every owned option and twin,** rather than looping over
  `owned-option-names`, a table only its own copy holds.

### 3.8 The seam's and the conventions' reviewed additions

- **check-seam:**
  - `(curl unsupported)` is a `(curl ...)` library no `(http-client ...)` library may import
    (ADR-0009, decision 1), which the seam already refuses. A new rule: no `(curl ...)` library
    imports it either, so `(curl)` cannot re-export the hatch past the first rule. It is
    watched failing;
  - filling a `struct curl_blob` needs `ftype-set!`, a reviewed addition to
    `allowed-chez-names`, for the one library that fills it. `getenv` is already allowed.
- **foreign-conventions:** no new entry point is planned. The body and the blob go through the
  pointer setopt binding, and the timings through the getinfo one.
- **test-constants:** `struct curl_blob`, `CURL_BLOB_COPY`, the new `CURLINFO`s and every classed
  `CURLE_*` code, each with a row. Each must exist in the floor's headers, or carry its gate:
  `CURLE_TOO_LARGE` 8.6.0 and `CURLE_ECH_REQUIRED` 8.8.0 (§3.4).

## 4. Slice 1: the request, its body, and the classes

### 4.1 First, measure

On the four Linux libcurls, and 8.23.0, each through a C probe against the test origin:
- **What a body sends,** byte for byte, through the byte probe: each method with a body of 0,
  1, 1,048,576 and 1,048,577 bytes, either side of libcurl's `Expect` threshold, and with none.
  §2 has the headers libcurl adds and the redirects; this adds the bytes and the sizes.
- **What suppresses libcurl's own headers,** on each libcurl.
- **What the connection phase covers:** whether `CONNECTTIMEOUT_MS` ends a TLS handshake the
  server never answers, and how a suite can stall a connect on loopback.
- **Each code a scenario can reach,** for the class table's scenario lists, and the timeouts.
- **The timings,** whether each is set, on scenarios whose phases are far apart, read as
  `curl_off_t`, on each libcurl.

**Measured, 2026-10-26** ([`research/m4/slice1/`](research/m4/slice1/)). A C probe made each
transfer through `curl_easy_perform`, against a capturing server, `capture.mjs`, and the test
origin with this run's PKI, on 7.85.0, Ubuntu's 8.5.0 with OpenSSL and with GnuTLS, Guix's
8.20.0 and 8.23.0:

- **Bodies.** All five sent the same heads, byte for byte, and every body whole, by its FNV-1a:
  - every body method's body carries `Content-Type: application/x-www-form-urlencoded`, an empty
    one too, and one past 1 MiB, 1,048,577 bytes, `Expect: 100-continue`; 1,048,576 does not;
  - to a server that never answers it, each waited 1,002 to 1,005 ms before sending the body;
  - with no body option, `PUT`, `PATCH` and `DELETE` send no `Content-Length`.
- **Suppression.** On all five, `Content-Type:` and `Expect:` in `HTTPHEADER` took libcurl's
  own away, and the wait with it. A request's own `Content-Type`, in any case, replaced
  libcurl's, before or after a `Content-Type:` in the list. A request's own `Expect:
  100-continue` was sent, and waited for, a `Expect:` beside it notwithstanding. `Content-Type;`
  sent an empty `Content-Type`.
- **The connection phase.** `CONNECTTIMEOUT_MS` ends a TLS handshake the server never answers,
  28 at about 300 ms, on all five: TLS to the raw face, which reads the ClientHello as the
  start of a head, and waits. That is how a suite stalls the connect phase on loopback, without
  stalling TCP. A connect timeout of 100 ms leaves a transfer that pauses 300 ms mid-body alone,
  and one of 300 ms leaves `/raw/stall-after-head` to its whole timeout.
- **The codes,** alike on all five: a refused connect, and a refused proxy, 7; a host, and a
  proxy, that do not resolve, 6 and 5; a timeout, 28; an untrusted, expired or wrong-host
  certificate, 60; a CA file that is missing, 77; a short body, 18; a close before any answer,
  52; a reset mid-body, 56.
- **The timings.** On a success all five report namelookup, connect, appconnect (0 over
  plaintext), pretransfer, starttransfer and total in that order, and a pause of 300 ms
  mid-body puts total 300 ms past starttransfer. These were fresh connections: on one reused,
  namelookup, connect and appconnect are 0 (8.20.0, the slice's review). On a failure they
  move with the version, and `CURLINFO_REQUEST_SIZE` does not: the maintainer chose it for a
  failure (§3.3; ADR-0022, amended 2026-10-26). It sums every send of every attempt, the
  body's too, so through one engine on 8.23.0, which resends a head after a dead reused
  connection, it is no head's length (ADR-0022, amended).
- **The options tables** (`options.c`): 313 options on 7.85.0, 318 on 8.5.0, 323 on 8.20.0 and
  327 on 8.23.0, aliases included; the owned list and its twins were read from their union
  (§3.2).

### 4.2 What it builds

- §3.1's request and response exports, §3.2, §3.3 but the waits, and §3.4.
- **`test-request`:** the keys, their refusals and defaults, each method with and without a
  body, the body's bytes as the origin received them, and the body copied. That last holds the
  engine with `call-with-engine-held` across the submit and the change, and asserts the token
  is still queued when the bytevector changes; otherwise a mutant that keeps the caller's
  bytevector passes whenever the engine copies it first.
- **`test-transfer`** asserts each answer's raised type against the class its code has in the
  suite's table (§3.4).

## 5. Slice 2: the asynchronous API

### 5.1 First, measure

- **Whether a process-directed SIGINT can land on the engine's thread,** on Linux and the Mac,
  with the main thread waiting in a take. The engine is public now, so a dropped Ctrl-C reaches
  callers (carried from M3 slice 1).
- **A take's delay** from completion to delivery, idle and under the gate's Valgrind.
- **The escape at the take:** an interrupt handler that escapes as the take's critical section
  ends, planted as `tests/engine-interrupt.sps` plants one in await, before the contract above
  is built on it.

**Measured, 2026-10-26** ([`research/m4/slice2/`](research/m4/slice2/)), on a prototype of the
take and the append, in the container (Guix's 8.20.0) and in Docker `ubuntu:24.04` (8.5.0,
Valgrind 3.22):

- **SIGINT.** 20 signals to the process, 300 ms apart, while a 9 s transfer was live, ran the
  keyboard-interrupt handler 20 times, with the main thread in a take, busy, or in a take
  beside a stalled lookup's resolver threads; and under Valgrind, 1 s apart, while a 30 s
  transfer was live: 160 of 160, and 120 of 120 in a rerun of the first three. No thread blocked any signal, so Linux's preference for the main thread is the
  whole of it. The maintainer chose to leave the engine's signal mask alone, and the Mac ran
  the probe on the slice's PR: 40 of 40 on the main thread, in a take and busy (ADR-0012,
  amended).
- **A take's delay** from completion: -0.2 to 9.6 ms idle and 0.05 to 8.9 ms under Valgrind,
  one polling sleep at most, as await's. The first run read 0.9 to 3.2 ms: its pauses, all
  multiples of 10 ms, met the waiter's sleeps at one phase (`traps.md`).
- **The escape.** With the mailbox's mutex held from another thread, a take blocked inside its
  critical section, and a SIGINT then sent ran its escaping handler as the section ended: the
  token out of the mailbox, never returned, deliver's callback unrun, and the token done, its
  200 awaited. An unheld control escaped before any token arrived. Chez's timer reaches no such
  place (`traps.md`). So the contract stands as written (ADR-0021, amended).

### 5.2 What it builds

- §3.1's engine, token and mailbox exports, §3.3's waits, and §3.5.
- **`test-mailbox`:** many tokens from two engines into one mailbox, each delivered once;
  take's bound; a callback's raise; a cancel's completion delivered; stop's `stopped` tokens
  delivered; an engine failure's tokens, and a set-up failure's, delivered; the delivery test;
  the escape at the take; and counts at zero.
- **A token completed twice is appended once.** A token cancelled while queued, then stopped or
  failed in the same batch, passes through the completion step twice. The append belongs to
  the change to done, so a mutant appending on every call fails "each delivered once" only if
  the suite drives that path, and it does.

**As built:**

- **`curl-submit` is the one submit;** the private `curl-engine-submit` is gone, and the test
  seam, `curl-engine-submit-with`, takes a mailbox too, so a set-up failure's delivery can be
  driven (slice 4 retires the seam).
- **Bounds are natural numbers of milliseconds.** A wait's last sleep stops at its bound, so a
  take answers `#f` within about a millisecond of it; the clock is read through
  `current-time`, `time-second` and `time-nanosecond`, a reviewed addition to check-seam's
  allowed names.
- **The escape's test plants it as the measurement did,** in a child, `tests/mailbox-escape.sps`:
  the mailbox held through a private seam, `call-with-mailbox-held`, and SIGINT from the suite.
- **The slice's review** (Opus, read-only) found every wait in `test-mailbox` timed only where
  it ran out: a wait that slept out its whole bound after one empty read passed all 24 checks.
  A take, a delivery and a token's wait, each bounded at 5 s, now return once a 300 ms transfer
  ends. Two places stay unchecked, recorded in the mutation log: the read a wait makes after its
  bound, and a cancel's append inside its critical section.

## 6. Slice 3: the environment (ADR-0024)

### 6.1 First, measure

- **When Guix's patch reads the variables,** which its source says is `global_init`: one set
  after the load, on Guix's 8.20.0, must change no transfer, and an empty one must count as
  unset.
- **Which spellings GnuTLS takes as PKCS#11:** `pkcs11:` and other cases, on 8.20.0 and Ubuntu's
  8.5.0. The refusal covers every ASCII case whatever this finds.
- **An `https://` proxy:** with `https_proxy` naming one, the request's `ca-file` and `verify`
  do not reach it, and a proxy whose certificate the system store does not trust is refused.

**Measured, 2026-10-26** ([`research/m4/slice3/`](research/m4/slice3/)), through a C probe with
chez-curl's TLS settings, on seven lanes: Guix's 8.20.0 in the container; in Docker
`ubuntu:24.04`, 7.85.0, Ubuntu's 8.5.0 with OpenSSL and with GnuTLS, 8.23.0, and Guix's 8.20.0
and 8.6.0 loaded from the store beside Ubuntu's libc (ADR-0024, amended):

- **When Guix's patch reads the variables:** at `curl_global_init`, and only then. On 8.20.0,
  in Guix and out of it, `SSL_CERT_FILE` set after the init changed nothing, one set before and
  unset after still replaced the CA file, and an empty one counted as unset. Guix's 8.6.0 lets
  a CA file win, and the maintainer kept it taken to override, since no lane runs it.
- **Which spellings GnuTLS takes as PKCS#11:** every ASCII case of `pkcs11:`, all sixteen, on
  GnuTLS 3.8.3, 3.8.9 and 3.8.13, even with a file of that name there. Near misses, and `p`, U+212A, `cs11:`,
  were read as files; the OpenSSL builds read every path as a file.
- **An `https://` proxy:** verified against the system store on every lane, whatever the
  request's `ca-file` and `verify` said; only `PROXY_CAINFO`, or the proxy's own verification
  off, reached it. Guix's libcurls take the proxy's CA from `SSL_CERT_FILE`.
- **And the plan's key:** `/proc/self/maps` maps `curl_version_info`'s entry point from the
  libcurl's own file, symlinks resolved. Spike E1's Chez, outside Guix, loaded Guix's 8.20.0,
  and the C probe showed that libcurl still overriding beside Ubuntu's libc: ADR-0002's
  world, libc's, would have missed it. The slice's review then loaded a copy out of the
  store, which overrode too; the maintainer added the patch's own string to the key
  (ADR-0024, amended: the key).

### 6.2 What it builds

§3.6, with a check for each refusal watched firing, and the proxy child judged by the proxy's
own log.

**As built:**

- **The key is the libcurl's own file:** the native layer records the `/proc/self/maps` line
  holding `curl_version_info`'s entry point, through `foreign-entry`, a reviewed addition to
  check-seam's names, for native alone. With none read, the path as loaded stands in. After
  the slice's review, which loaded a copy of Guix's 8.20.0 out of the store and saw the CA
  file replaced unrefused, the maintainer added the patch's own literal, `SSL_CERT_FILE`, in
  that file (ADR-0024, amended: the key).
- **The refusal's rule is pure,** `overriding-variables`, over native's records, so every lane
  holds it with synthetic inputs, and `test-transfer-tls` holds the shell that calls it, and
  `prepare-transfer`'s call, whole. Only the container's Guix libcurl shows it by behaviour.
  The pin's child now sets or empties a variable after the load too, and prints native's
  record after that, which tells native's reading at the load from one a submit might make,
  on every lane.
- **The pin no longer sees the override itself:** the refusal stands in front of it. The
  measurement is its evidence, rerun for a new Guix version by `research/m4/slice3/run.sh`'s
  `when` set, which the pin names when a Guix libcurl has no row.
- **The stand-in proxy is the origin's http face.** The origin routes a target in absolute
  form by its path, so `/echo`'s first line is the proxy's own record of the request: an
  absolute target through a proxy, a path direct.
- **`PROXY`'s twins:** `NOPROXY`, `PRE_PROXY`, `PROXYPORT` and `PROXYTYPE`, by the rule slice 1
  used for `PORT`. Slice 4 reads its full list from the options tables.
