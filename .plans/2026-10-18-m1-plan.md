- **Scope:** brief §7 and §8's M1: the local origin, the per-run test CA, and the drift guard,

## 2. How the instrument is checked

Chez has no sockets: no name with `socket`, `tcp` or `connect` in it is in Chez 10.4.0's
`(scheme-environment)` (measured 2026-10-18). With no client yet, a Chez suite reaches the
origin only through another process. The maintainer chose (2026-10-18):

- **A byte probe.** `tests/wire-probe.mjs` uses `node:net` (and `node:tls` in slice 2) and
  nothing that knows HTTP. It sends the bytes it is given, and reports every byte it
  receives, so nothing between the origin and the suite normalises framing.
- **The suite holds its own copy of every expected output,** written in Chez, never read
  from `origin.mjs`. Changing a scenario's bytes in the origin fails the suite. Assert whole
  outputs: every byte, and how the connection ended.
- **Certificates are checked with `openssl`,** by verify code (slice 2), independent of Node
  and libcurl.
- **No check uses libcurl or the `curl` command line.** The instrument is not judged by the
  library it will test.

## 3. The origin's contract

ADR-0005's contract, made exact:

- `node tests/origin.mjs` takes no arguments in slice 1. Slice 2 adds `--pki DIR` (§8.2). Any other
  argument makes it exit 2, with a message on stderr.
- **Each face listens on `127.0.0.1`, port 0.** The OS picks the port.
- **The announcement:** once every face is listening, one line on stdout, a flat JSON
  object. Nothing else ever goes to stdout.

  ```
  {"node":"v24.18.0","pid":12345,"http":"127.0.0.1:40001","raw":"127.0.0.1:40002"}
  ```

  - `node` is `process.version`, and `pid` is `process.pid`.
  - Each face's value is `ADDRESS:PORT`, both read back from `server.address()` once it
    listens, never from what was asked for.
  - The keys come in this order, with no others. Slice 2 adds its faces after `raw` (§8.2).
- **It exits 0 when its stdin closes,** after closing every listener and destroying every
  open socket. It writes nothing to stderr unless it fails.
- **Its stdin closes once every process holding it has gone.** That means its suite, and
  any probe or command the suite was running: Chez's `system` children inherit the pipe's
  write end. So a suite that dies mid-probe leaves the origin serving until that probe
  ends, within `wire-probe-deadline` (30 s by default), or `bounded`'s 10 s. Measured: 19.3
  s after a SIGKILL during an idle-bounded probe.
- **A client that misbehaves never stops it.** Resets, half-closes, garbage, and a client
  vanishing mid-script each end that connection only. The raw face allows half-open
  connections, so a client that half-closes after its request still gets its whole
  script.
- **Any other error goes to stderr and exits 1.** `call-with-origin` holds every origin to a
  clean stop (§6), so a suite sees the origin die rather than pass without it.

## 4. The plaintext scenarios (slice 1)

### The well-formed face, `http`

It is built on `node:http`. Every response is deterministic: no `Date` (`sendDate = false`),
and headers written in a fixed order. A request carrying `Connection: close` gets
`Connection: close` back.

| Request | Response |
|---|---|
| `GET /status/CODE`, CODE 200–599 | status CODE, body `status CODE\n` |
| `GET /redirect/CODE?to=TARGET`, CODE 300–308 | status CODE, `Location:` the decoded TARGET, body `redirect CODE\n` where the status allows one |
| `GET /chunked` | `Transfer-Encoding: chunked`, three writes, `alpha\n`, `beta\n` and `gamma\n`, each its own chunk |
| `ANY /echo` | status 200, body: the request line as Node parsed it, then each header from `rawHeaders` in order, as `Name: value`, then a blank line, then the request body. Each line ends `\n` |
| anything else | 404, body `not found\n` |

What Node puts on the wire for each is measured, and the suite holds those bytes. Node
20.10.0 and 24.18.0 write the same bytes for every one. 204 and 304 carry no body and no
`Content-Length`, and 205 carries `Content-Length: 0`.

### The raw face, `raw`

It is built on `node:net`. Per connection it reads the request head, up to the first
`\r\n\r\n`, and gives up on one longer than 64 KiB. It takes the target from the request line,
`/raw/NAME` with an optional `?QUERY`, and plays NAME's script. Then it closes, so there is no
keep-alive.

- **A script is a list of steps:** write these bytes, wait N ms, end (FIN), reset (RST), or
  stall (write nothing until the client goes).
- **An unknown NAME or parameter, or one out of range, gets a fixed 400**, then the
  connection closes.

| Group | NAME | What it plays |
|---|---|---|
| framing | `content-length` | `HTTP/1.1 200 OK`, `Content-Length: 6`, `hello\n`, FIN |
| | `chunked` | `Transfer-Encoding: chunked`, chunks `hello` and `\n`, the last chunk, FIN |
| | `chunked-extensions-trailers` | chunk extensions, an upper-case hex size, a trailer section |
| | `chunked-tiny` | `hello\n` in one-byte chunks |
| | `close-delimited` | `Connection: close`, no length, `hello\n`, FIN |
| | `http10` | `HTTP/1.0 200 OK`, no length, `hello\n`, FIN |
| drips | `drip?bytes=N&gap=MS` | a head with `Content-Length: N`, then N bytes, one every MS ms. N 1–4096, MS 1–5000 |
| | `stall-after-head` | a head with `Content-Length: 6`, then stall |
| | `stall-before-head` | reads the request, then stall |
| | `pause-mid-body?ms=N` | a head with `Content-Length: 11`, `hello`, a wait of N ms, ` world`, FIN. N 1–60000. Added in slice 2, so the stop check can hold a script still playing (§8.6) |
| oversized | `big-header?bytes=N` | one header, `X-Big:` and N bytes of `a`. N 1–1048576 |
| | `many-headers?count=N` | N headers, `X-H-1: v` to `X-H-N: v`. N 1–100000 |
| protocol errors | `bad-status-line` | `HTP/1.1 200 OK` |
| | `bad-status-code` | `HTTP/1.1 2000 OK` |
| | `bad-chunk-size` | a chunk size of `zz` |
| | `short-body` | `Content-Length: 10`, 5 bytes, FIN |
| | `reset-mid-body` | `Content-Length: 10`, 5 bytes, RST |
| | `conflicting-content-length` | `Content-Length: 5` and `Content-Length: 6` |
| | `chunked-and-content-length` | both framings at once |
| | `header-no-colon` | a header line with no colon |
| | `nul-in-header` | a NUL inside a header value |
| | `close-before-response` | reads the request, then FIN with nothing written |
| | `http09` | `hello\n` with no status line, FIN |
| tolerated | `bare-lf` | `HTTP/1.1 200 OK`, every line ending `\n` alone |
| echo | `echo` | `HTTP/1.1 200 OK` with a `Content-Length`, and the request head's exact bytes as body |

The builder writes each script's bytes. The suite's copy is written separately from that.

Drips stay small in the suite, a few bytes at tens of milliseconds, because `test-origin`
runs in every `make test` and under the memory gate. (`check-test-fails` deletes the real
suites in its copy, so it never runs them.)

## 5. The probe

```
node tests/wire-probe.mjs [--reset | --half-close] [--deadline MS] HOST PORT HEX IDLE-MS
```

- It connects and sends HEX's bytes once. HEX is pairs of lower-case hex digits, or
  `@FILE`, a file holding them, for more bytes than one argument can carry.
- It prints Scheme data on stdout, one datum per line. Times are whole milliseconds since it
  started.
  - `(connected MS)`, taken before it sends a byte.
  - `(data OFFSET MS "HEX")`, one per chunk it reads. Chunk boundaries are not part of any
    contract.
  - `(end KIND MS)`, where KIND is `eof`, `reset`, `timeout` (IDLE-MS passed with no data)
    or `deadline` (the whole run reached `--deadline`, 30000 by default), or `error`
    followed by the error's code. On `timeout` and `deadline` it destroys the socket.
  - `(reset-sent MS)`, with `--reset`, in place of any end line. Once its bytes are with the
    kernel, it resets the connection with `resetAndDestroy()`. A `destroy()` reaches the
    peer as a FIN, never a reset (measured).
  - `(refused "CODE" MS)` when the connection fails.
- With `--half-close`, it ends its side once its bytes are with the kernel, and goes on
  reading. Otherwise it never half-closes.
- It exits 0 when it ran, and 2 on a usage error.
- Slice 2 adds `--tls SERVERNAME` and `--alpn LIST` (§8.3). The probe never judges a
  certificate.

## 6. The helpers in `(curl-testing)`

Each export has a type signature and tests in `test-curl-testing`.

- **`call-with-origin : (Origin -> Any) -> Any`**
  - It runs `$NODE` on `origin-script` (a parameter, `tests/origin.mjs` by default) under a
    small `sh` runner, which records node's pid and, once node exits, its exit status. Chez
    has no `wait`. `NODE` comes from the environment, or defaults to `node`.
  - It reads the announcement within `origin-timeout` (a parameter, 5000 ms), and requires
    the announced pid to be the recorded one.
  - It answers `(PROC origin)`, then closes the origin's stdin. Once PROC returns, it
    requires all of these, within the bound:
    - stdout ends;
    - nothing is written after the announcement;
    - nothing is on stderr;
    - the exit status is 0.

    Every raise carries the stdout, stderr and status it saw.
  - When PROC raises, that raise goes on unchanged, and the origin is still stopped, or
    killed.
- **`origin-node`, `origin-pid` and `origin-face`** read the announcement. An unknown face
  raises.
- **`read-announcement : String -> (Listof (Pair String (U String Natural)))`**
  - It is strict: one flat JSON object, with string keys, and values that are strings or
    naturals.
  - It refuses escapes, nesting, duplicate keys and trailing text, by raising.
- **`read-within`** reads a port, bounded by a monotonic deadline that it checks before
  every read, and by size. Every wait on a pipe, in the helpers and the suites, uses it or
  such a deadline. `capture-command`'s `system` waits with no clock: each command it runs
  is bounded by its own deadline, or by `bounded`.
- **The probes.**
  - `wire-probe : Origin Symbol Bytevector Natural -> Probe` runs the probe against a face,
    with an idle bound.
  - `wire-probe-reset` and `wire-probe-half-close` do the same with `--reset` and
    `--half-close`.
  - `wire-probe-deadline` is a parameter: how long any probe may run in all.
  - Bytes beyond 16384 go through a temporary `@FILE`.
- **`parse-wire-probe : String -> Probe`** reads the probe's output strictly.
- **A Probe holds:** `probe-bytes`, all the bytes received; `probe-end`; `probe-arrivals`,
  each chunk as `(offset . ms)`; and `probe-connected`.

## 7. Lifecycle checks

- **Loopback only.**
  - Every face's announced address is `127.0.0.1`.
  - On Linux, each face also refuses a connection to `127.0.0.2:PORT`, so a face bound to
    any address fails even if it announces loopback. Elsewhere this test is skipped, since
    `127.0.0.2` isn't a loopback address there by default.
- **OS ports.** Two origins at once announce different ports, and both serve.
- **A clean stop.** After `call-with-origin` returns, every face refuses connections.
  Stand-ins that exit 1, write to stderr, flood stdout, or die after an answer each make it
  raise, by name.
- **Open connections are destroyed.** A probe still connected when PROC returns sees eof,
  and the call returns promptly.
- **It outlives its suite only by a bound.** A child Chez starts an origin and reports its
  ports, then is killed with SIGKILL while idle: within 5 s, every face refuses connections.
  Killed mid-probe instead, every face refuses within the probe's deadline.
- **Survives a bad client.** After a reset mid-request, a half-close, and a client that
  vanishes during a drip, the next probe is served.
- **No helper outlives its call:** not the probes, the watchdogs, the child Chez, nor the
  stand-ins.
- **Timing.** A drip's body byte i arrives at least (i+1)×gap after the probe connected. The
  last arrives at least half of (N−1)×gap after the first, and on the 25 ms row each body
  byte arrives alone.
- **Ranges.** Every parameter is served at both edges of its range, and refused just
  outside them.
- **The 64 KiB head limit,** from both sides.

## 8. TLS and HTTP/2 (slice 2)

Settled 2026-10-18, from measurements recorded in the [TLS mutation log](tls-mutation-log.md). The maintainer chose portable checks only (§8.6).

### 8.1 The material: `tests/make-test-pki.sh DIR`

- DIR must be an existing, empty directory, or it exits 2.
- On success, DIR holds exactly ten files, nothing goes to stdout or stderr, and it exits 0:

  | File | What it is |
  |---|---|
  | `ca.pem` | the run CA, the one a suite trusts |
  | `other-ca.pem` | a second CA, never trusted |
  | `good.pem`, `good.key` | for `localhost`, `127.0.0.1` and `::1`, signed by the run CA |
  | `expired.pem`, `expired.key` | as good, valid only 2000-01-01 to 2000-01-02 |
  | `wrong-host.pem`, `wrong-host.key` | for `wrong-host.invalid` only, signed by the run CA |
  | `untrusted.pem`, `untrusted.key` | as good, but signed by the second CA |

- **Each failing leaf has one fault the good one lacks:** its dates, its names, or its
  issuer. Every leaf's subject is `CN=chez-curl test leaf`, which names no host.
- **Keys are EC P-256, and signatures ECDSA with SHA-256.** The CAs and every leaf but the
  expired one last two days.
- **DIR may be relative.** The script makes it absolute before it `cd`s, so its exit trap
  still removes `work/`. The review found a relative DIR exiting 0 and leaving `work/`,
  CA keys included.
- A failing `openssl` command exits 1, with openssl's output on stderr.
- It runs `$OPENSSL`, else `openssl`.
- **Measured on four implementations** (OpenSSL 3.5.7, 3.0.13, 3.0.11; LibreSSL 3.3.6), under
  bash and dash. LibreSSL's `req` takes the config's subject over `-subj` when the config
  says `prompt = no`, so the script's config has no subject.

### 8.2 The faces

`node tests/origin.mjs [--pki DIR]`. The plaintext faces are always there. `--pki DIR` adds
the TLS faces, which read DIR's leaves.

| Face | Built on | Leaf | ALPN it accepts | Serves |
|---|---|---|---|---|
| `http` | `node:http` | none | none | §4 |
| `raw` | `node:net` | none | none | §4 |
| `h2c` | `node:http2`, prior knowledge | none | none | the HTTP/2 routes |
| `https` | `node:https` | good | `http/1.1` | `http`'s routes and bytes |
| `https-expired` | `node:https` | expired | `http/1.1` | the same |
| `https-wrong-host` | `node:https` | wrong-host | `http/1.1` | the same |
| `https-untrusted` | `node:https` | untrusted | `http/1.1` | the same |
| `raw-tls` | `node:net`, each socket wrapped in `tls.TLSSocket` | good | `http/1.1` | `raw`'s scripts |
| `h2` | `node:http2`, secure, no HTTP/1.1 | good | `h2` | the HTTP/2 routes |

- **The announcement's keys,** in this order: `node`, `pid`, `http`, `raw`, `h2c`, then, with
  `--pki`, `https`, `https-expired`, `https-wrong-host`, `https-untrusted`, `raw-tls`, `h2`.
- **The HTTP/2 routes** follow `http`'s, with the same paths, ranges and bodies:
  - `GET /status/CODE` answers `:status`, then `content-length`. 204 and 304 send no
    `content-length` and no body, and 205 sends `content-length: 0`.
  - `GET /redirect/CODE?to=TARGET` answers `:status`, `location`, `content-length`.
  - `ANY /echo`: the body is each `rawHeaders` pair as `name: value\n`, pseudo-headers
    included, in order, then `\n`, then the request body.
  - Anything else gets 404, `not found\n`. `/chunked` is an HTTP/1.1 route, so it's 404 here.
  - No `date` (`sendDate: false`), and no header beyond those listed.
- **Measured:** Node 20.10.0 and 24.18.0 write the same HTTP/2 bytes, over TLS and in
  plaintext. Each sends an empty SETTINGS frame by default. The HEADERS blocks:

  | Answer | HEADERS block |
  |---|---|
  | `GET /status/200` | `88 0f 0d 02 31 31` |
  | 204, with END_STREAM | `89` |
  | 304, with END_STREAM | `8b` |
  | 205 | `48 82 10 1b 0f 0d 01 30` (`:status` in Huffman code) |
  | 404 | `8d 0f 0d 02 31 30` |

- **Measured for bad HTTP/2 clients**, alike on both versions:
  - HTTP/1.1 sent to `h2c` or `h2` gets SETTINGS, then GOAWAY with last stream 0 and
    INTERNAL_ERROR;
  - a stream reset with PROTOCOL_ERROR gets SETTINGS, the ACK, then eof. Without a stream
    error listener, the origin dies of `ERR_HTTP2_STREAM_ERROR`.
  - At stop, each session sends two GOAWAY frames, then eof.
- **On `h2`, a client that does not choose `h2`** gets its socket destroyed at once, by an
  `unknownProtocol` listener. With no listener, Node 20.10.0 and 24.18.0 both write
  `HTTP/1.0 403 Forbidden` and a text body, then close (measured by the review). A client
  would read that as a response. Measured with the listener:
  - a client offering no ALPN connects, then sees eof;
  - one offering only `http/1.1` is refused in two ways. Node 24 sends the
    `no_application_protocol` alert, and Node 20 closes before the handshake ends, which
    the probe reports as `(refused "EOF" MS)`. The suite accepts exactly those two.
- **A reset on `raw-tls`** resets the wrapped TCP socket: `resetAndDestroy()` on a TLS
  socket throws `ERR_INVALID_HANDLE_TYPE` in both Node versions (measured). The client sees
  the data, then the reset.
- **The contract stands for every face.**
  - Each face listens on `127.0.0.1`, port 0.
  - A client's TLS or HTTP/2 error ends only that connection.
  - Stopping closes every listener and destroys every socket and HTTP/2 session.
- **A wrong argument exits 2,** and so does a PKI file it cannot read, naming the file. So
  does a leaf whose key does not match it: that names both files, and the code
  `ERR_OSSL_X509_KEY_VALUES_MISMATCH`, the same on both Node versions.

### 8.3 The probe

`--tls SERVERNAME` and `--alpn LIST` join §5's options.

- **`--tls SERVERNAME`** speaks TLS, verifying nothing, with SNI SERVERNAME, which must be a
  DNS name. The probe never judges a certificate.
- **`(connected MS)`** comes once the handshake is done. A handshake that fails is
  `(refused "CODE" MS)`.
- **`--alpn LIST`** offers a comma-separated list of protocols, and only with `--tls`. A
  protocol named twice is a usage error.
- **`--reset` with `--tls` is a usage error.** Resetting the TCP socket under a client TLS
  socket reached the server as a FIN (measured).
- **`--half-close` with `--tls`** ends the TLS side and goes on reading. Measured on both
  Node versions: after `end()`, a `raw-tls` drip still delivered its bytes at 100, 200 and
  300 ms.
- **A TLS peer that closes before the handshake is done** gives `(refused "EOF" MS)`.

### 8.4 The helpers in `(curl-testing)`

- **`origin-pki`** is a parameter, `#f` or a directory. With a directory, `call-with-origin`
  passes `--pki DIR`.
- **`make-test-pki : -> String`** makes a process temp directory and runs `sh` on
  `test-pki-script` (a parameter, `tests/make-test-pki.sh` by default) into it. It requires
  exit 0, empty stdout and stderr, and the ten files. It raises with all it saw.
- **`wire-probe-tls`** is a parameter: `#f`, or a list of SERVERNAME and then the ALPN
  protocols. Every probe made while it is set runs with `--tls`, and `--alpn` when given.
  `wire-probe-reset` raises under it, before running.
- **`bounded`** moves here from `test-origin`: `capture-command` under `timeout 10`
  (`timeout` or `gtimeout`).
- **`openssl-program`** is `OPENSSL` from the environment, else `openssl`.
- **`s-client : Origin Symbol (U String #f) String (U String #f) -> Peer`**: ORIGIN,
  FACE, SERVERNAME, CA and ALPN. It runs, under `bounded`:

  ```
  $OPENSSL s_client -connect ADDRESS:PORT [-servername NAME] -CAfile CA -showcerts [-alpn LIST] </dev/null
  ```

  With SERVERNAME `#f` it sends no SNI, as libcurl sends none to an IP address. Measured
  on OpenSSL 3.5.7 and 3.0.11, and LibreSSL 3.3.6: without `-servername`, `s_client`
  sends no SNI to an IP address.

  It requires exit status 0. `parse-s-client : String String -> Peer` reads stdout and
  stderr. Missing or duplicated lines raise, except the code's (below):
  - **`peer-verify-errors`** come from stderr: every `verify error:num=N:` line, in order.
  - **`peer-verify-code`** comes from stdout's first `Verify return code: N (…)` line, the
    handshake's. LibreSSL indents it.
    - **OpenSSL 3 prints one more such line for each TLS 1.3 session ticket** it reads
      before stdin ends, inside a `Post-Handshake New Session Ticket arrived:` block. How
      many it reads depends on timing (`traps.md`).
    - So each later code line needs its own ticket header, and must carry the same code.
      Every ticket's code matched the handshake's on every face (measured).
    - Anything else raises: a code line with no header, a header with no code, or a code
      that differs.
  - **`peer-alpn`** is stdout's one `ALPN protocol: X` line, or `#f` for its one
    `No ALPN negotiated` line.
  - **`peer-chain`** is every certificate block's base64 text, newlines dropped, in order.
    **`peer-leaf`** is the first.
- **`certificate-text`** runs `$OPENSSL x509 -in FILE -noout -text` under `bounded`, and
  answers its lines, trimmed. It raises unless the status is 0.
  - **`certificate-values`** reads the values after a prefix, such as
    `Signature Algorithm:`.
  - **`certificate-time`** reads a `Not Before` or `Not After` date as seconds.
  - **`certificate-san`** answers the line after `X509v3 Subject Alternative Name:`, and
    raises when that line is missing or twice.

  OpenSSL 3.5.7 and 3.0.11, and LibreSSL 3.3.6, print the same trimmed fact lines: the
  signature algorithm, the curve, the key size, and both dates.
  - **`certificate-names`** reads the `Subject:` and `Issuer:` values, with ` = ` folded to
    `=`. OpenSSL 3.0 writes `CN = x`, where 3.5.7 and LibreSSL write `CN=x`. It refuses
    any other label. No check reads the `-subject` option's line.
- **`probe-ended : Probe -> Natural`** is the end line's milliseconds, so a test can assert
  a bound the idle timer does not hold. Before a TLS handshake ends, only `--deadline`
  holds the probe.
- **`pem-certificate : String -> String`** is a PEM file's first certificate's base64
  text, newlines dropped, read in Scheme.

### 8.5 What `openssl` showed (measured on all four)

Each implementation gave the same answers, against Node serving each leaf:
- exit status 0;
- the same verify errors, the same final code and the same ALPN line;
- a served leaf equal to its file;
- the same SAN text.

LibreSSL 3.3.6 has no `-verify_hostname`, `-verify_ip`, `-checkhost` or `-ext`.
Its `s_client -verify_return_error` exits 0 on a failed verify. The `-subject` line's format
differs between them, so no check reads it.

### 8.6 The checks: `tests/test-origin-tls.sps`

One PKI per suite run. Offered ALPN is `h2,http/1.1`, and the good SAN is
`DNS:localhost, IP Address:127.0.0.1, IP Address:0:0:0:0:0:0:0:1`.

| Face | Verify errors | Code | ALPN | Served leaf | That leaf's SAN |
|---|---|---|---|---|---|
| `https` | none | 0 | `http/1.1` | good | good |
| `https-expired` | 10 | 10 | `http/1.1` | expired | good |
| `https-wrong-host` | none | 0 | `http/1.1` | wrong-host | `DNS:wrong-host.invalid` |
| `https-untrusted` | 20, 21 | 21 | `http/1.1` | untrusted | good |
| `raw-tls` | none | 0 | `http/1.1` | good | good |
| `h2` | none | 0 | `h2` | good | good |

- **Trust:** `untrusted.pem` verifies against `other-ca.pem`, and `good.pem` does not.
- **The material:**
  - DIR's listing is exactly the ten files, for an absolute DIR and for a relative one.
  - Each refusal exits 2. A failing `openssl` exits 1, with stderr, and leaves no `work/`.
  - Every CA and leaf has a P-256 key, and both its signature algorithms are ECDSA with
    SHA-256.
  - Each but `expired` lasts two days: 172800 s, or 172801 s when a second ticks between
    `openssl`'s two clock reads. `expired` is exactly 2000-01-01 to 2000-01-02.
  - Every leaf's subject is `CN=chez-curl test leaf`, and each CA's subject and issuer
    its own CN. Each leaf's issuer is the run CA, except `untrusted`'s, which is the
    second CA.
- **Each face's chain is its leaf alone.**
- **With no SNI,** every TLS face serves the Peer it serves with SNI `localhost`.
- **Each face's ALPN set is pinned:** it is offered `h2`, `http/1.1` and an unknown
  protocol, each alone.
  - Its own protocol is chosen.
  - Each other is refused with alert 120, no_application_protocol. `s_client` then exits 1,
    still writes `No ALPN negotiated`, and prints no certificate. This is measured on every
    face, on both Node versions, with all three checkers.
  - A face with no TLS gives that same row. So each refusal also requires
    `alert number 120` on stderr, which every checker writes for a real refusal only.
- **Every claimed bound is asserted:** a test that says "within N ms" checks the probe's
  own times.
- **Bytes over TLS,** the suite's own copy:
  - each `https` face serves `http`'s bytes for `GET /status/200` and for an `/echo` with a
    body;
  - `raw-tls` plays a sample of `raw`'s scripts byte for byte, `reset-mid-body` ending in
    `reset`;
  - its drip gets every body byte at least half the gap after the one before. TLS hands
    each record over as its own chunk, so slice 1's "each byte alone" says nothing here
    (`traps.md`).
- **HTTP/2, on `h2c` and over TLS on `h2`.** The suite builds each frame from length, type,
  flags, stream and payload. Its requests are the connection preface, an empty SETTINGS
  frame, and a HEADERS frame, sent with `--half-close`.
  - `GET /status/200` gets exactly: SETTINGS, SETTINGS ACK, HEADERS `88 0f 0d 02 31 31`,
    DATA `status 200\n` with END_STREAM, then eof.
  - The 404 and 204 answers are asserted too.
  - On `h2`, a client offering no `h2` sees its end within 1 s.
- **Every HTTP/2 route's bytes** are asserted on `h2c`: each status class, the redirect,
  echo, and `/chunked`'s 404.
- **Bad clients:**
  - plaintext sent to a TLS face, and a partial ClientHello then a reset;
  - HTTP/1.1 sent to an HTTP/2 face, and a stream reset with PROTOCOL_ERROR.

  After each, the next probe is served.
- **The ticket rule against real output:** `https-untrusted`, with stdin ending 300 ms late,
  parses to the same Peer. Its count of code lines is one more than its ticket headers.
- **The probe's ALPN:** stand-ins report the client's whole offered list, through
  `ALPNCallback`, since the chosen protocol follows the server's preference. Rows overlap
  only in the first protocol offered, only in the last, and only in the middle of three.
- **Lifecycle:**
  - every face is on `127.0.0.1`, and on Linux refuses `127.0.0.2`;
  - every face refuses once `call-with-origin` returns;
  - **each open connection ends only because of the stop,** by this mechanism:
    - **The states Node's own `close()` doesn't end are covered.** The origin exits only
      once every face's `close()` has seen each connection end. So the call returning
      soon after PROC bounds every close, for each of these per-face waiting states:

      | Face | Waiting states |
      |---|---|
      | `https` ×4 | nothing sent; a partial ClientHello; the handshake done; a partial head; idle after a keep-alive response; a head sent, its body to come |
      | `raw-tls` | nothing sent; a partial ClientHello; the handshake done; a partial head; a stall before its head; a stall after it; a script playing, between two of its writes; the same, the client half-closed |
      | `h2` | nothing sent; a partial ClientHello; the handshake done; a partial preface; the preface done; a stream open, its body to come |
      | `http` | nothing sent; a partial head; idle after a keep-alive response; a body to come |
      | `raw` | nothing sent; a partial head; a stall before its head; a stall after it; a script playing, between two of its writes; the same, the client half-closed |
      | `h2c` | nothing sent; a partial preface; the preface done; a stream open, its body to come |

      Measured, with nothing tracked:

      | Face | What Node 24.18.0's `close()` ends | Node 20.10.0's |
      |---|---|---|
      | `http`, `https` | idle after a keep-alive response, within 1 ms | the same |
      | `raw`, `raw-tls` | nothing | nothing |
      | `h2c` | sessions with nothing sent, a partial preface, or the preface done, within 3 ms | nothing |
      | `h2` | sessions past the handshake, within 2 ms | nothing |

      Neither version ever ends a stream with its body to come, nor a TLS state before
      the handshake.
    - **Silence up to the stop.** Each probe is read once more just before PROC returns,
      and must hold its state: `(connected …)`, exactly that state's bytes, and no end.
    - **A tight bound, B = 500 ms,** from PROC's return to the call's, both on Chez's
      monotonic clock. Measured on a correct origin:
      - on the container's CPUs: 34–46 ms idle (`measure5/stop-spread-idle.txt`),
        70–150 ms under 24 busy loops, and 49–76 ms with Chez under Valgrind;
      - on 2 CPUs: 129–177 ms;
      - on 1 CPU, under Valgrind or 2 busy loops: 301–324 ms, the worst. CI runners have
        2–4 vCPUs.
    - **Each probe ends in eof,** or in a reset when a starved origin destroys a socket
      with the client's bytes unread.
    - **Two sets, 700 ms apart (Δ > B).** No timer keyed to each connection can end both
      inside the window: one set would end before the stop, or the other more than B after
      it.
    - **The check runs twice, on fresh origins, the second with both sets held 700 ms
      longer before the stop.** The third review's watchdog and load-shedding mutants
      ended every connection at one shared time, after the stop, which two sets alone
      cannot rule out. A schedule fixed to the origin's start, or to the sets' opening,
      cannot fall inside both runs' windows.
    - **What the tests claim:** each waiting state its table names, and each probe's end
      the stop's. The stop is a destroy or an exit. Each closes every socket alike at the
      TCP level, so no check tells them apart (§8.8). The suite's comment names three
      states no check holds:
      - an HTTP/2 response its client's flow-control window holds back;
      - a TLS handshake whose whole ClientHello came, but not the client's Finished;
      - a response the client does not read.
    - **Validated by a sweep:** each of the 9 faces untracked, and closed L ms after each
      accept, for L from 100 to 5000 ms, or never. All 90 cases failed on Node 24.18.0,
      and all 90 on Node 20.10.0 (the TLS mutation log, Part 4). The second hold broke
      none of them (Part 5).

    Slice 1's plaintext faces are held to the same rule.

### 8.8 Not in slice 2, and what later milestones need

- **Not built:**
  - raw HTTP/2 frames that nghttp2 refuses to send (M7);
  - a TLS reset from the probe;
  - hostname verify codes: LibreSSL has none, so the SAN line stands in;
  - faces on `::1`, though the good leaf already names it.
- **Limits, measured:**
  - **On Node 20.10.0, an HTTP/2 connection error leaves the connection open.** After the
    origin's GOAWAY with PROTOCOL_ERROR, for DATA on stream 0, nothing fires: no `error`,
    `frameError`, `goaway`, `close` or `sessionError`. So the connection stays open until
    the client goes. Node 24.18.0 emits `sessionError` and closes.
  - **The SIGKILL outlive check runs without `--pki`.** The stop path is shared.
  - **The faces don't pin a TLS version.** Both Node versions negotiate TLS 1.3 with every
    checker.
  - **The stop check cannot tell a destroy from an exit.** An origin that calls
    `process.exit` at stop ends every connection the same way at the TCP level, so it
    passes.
  - **Sparing only the HTTP/2 states that Node 24's `close()` ends** is caught on Node 20
    only: CI's floor lane, and the Docker run. Sparing a whole face fails everywhere,
    since every face has states `close()` never ends.
- **For M2 and later:**
  - **Assert the good face is accepted, on each TLS backend, as the control.** libcurl
    returns `CURLE_PEER_FAILED_VERIFICATION` for all three faults, so a refusal alone
    proves nothing.
  - A face offering both `h2` and `http/1.1`, to test ALPN preference.
  - HTTP/2 drips and streams (M7).
  - **A TLS handshake that stalls is already at hand:** a TLS client sent to the plaintext
    `raw` face gets no ServerHello.

## 9. The drift guard (ADR-0017)

- `tests/known-libcurls.sexp` lists the libcurls the suites have been recorded against. Each
  row has a label, `where`, and the five fields compared exactly: `version`, `version-num`,
  `features`, `ssl-version` and `host`.
- **`test-drift` passes only when `(loaded-libcurl)`'s five fields equal exactly one row's.**
  It fails on any other libcurl, and prints that library's row, ready to add.
- A malformed file, a duplicate row, or a row with a missing or extra field fails by name,
  never as a suite that dies unnamed.
- **Rows at slice 1:**
  - the Guix container;
  - Ubuntu 24.04's `libcurl4t64`, which CI's `main` and `memory` lanes load;
  - the 7.85.0 floor that `scripts/ci/build-curl.sh` builds.

  The last two are measured in Docker with `tests/libcurl-oracle.c`. The Mac has no row until
  its first run.
- **The floor build becomes deterministic.** `build-curl.sh` runs `./configure
  --with-openssl` and lets `configure` find whatever optional libraries the machine has. So
  the floor's feature word could differ between Docker and the runner. Every optional
  library becomes an explicit `--with-…` (its `-dev` package listed in
  `packaging/debian-prereqs.txt`) or `--without-…`/`--disable-…`. RTSP stays on:
  `test-variadic` needs it.

  `${{ steps.ID.outputs.NAME }}`, matching the key in any case, quoted or not.
