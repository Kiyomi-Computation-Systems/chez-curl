# M1 plan: the test instrument

- **Date:** 2026-10-18
- **Status:** accepted for slice 1
- **Scope:** brief §7 and §8's M1: the local origin, the per-run test CA, and the drift guard,
  with no client
- **Records:** [ADR-0005](decisions/0005-node-test-origin.md) (amended 2026-10-18) ·
  [ADR-0017](decisions/0017-drift-guard.md) · [global-constraints](global-constraints.md)

M1 builds the instrument before the thing it measures. Nothing under `src/` changes, and no
M1 code binds libcurl. The drift guard loads libcurl through `(curl)`, which M0 built.

## 2. How the instrument is checked

Chez has no sockets: no name with `socket`, `tcp` or `connect` in it is in Chez 10.4.0's
`(scheme-environment)` (measured 2026-10-18). With no client yet, a Chez suite reaches the
origin only through another process. The maintainer chose (2026-10-18):

- **A byte probe.** `tests/wire-probe.mjs` uses `node:net` (and `node:tls` in slice 2) and
  nothing that knows HTTP. It sends the bytes it is given, and reports every byte it
  receives, so nothing between the origin and the suite normalises framing.
- **The suite holds its own copy of every expected output,** written in Chez, never read
  from `origin.mjs`. Changing a scenario's bytes in the origin fails the suite. Assert whole
  outputs: every byte, and how the connection ended.
- **Certificates are checked with `openssl`,** by verify code (slice 2), independent of Node
  and libcurl.
- **No check uses libcurl or the `curl` command line.** The instrument is not judged by the
  library it will test.

## 3. The origin's contract

ADR-0005's contract, made exact:

- `node tests/origin.mjs` takes no arguments in slice 1. Slice 2 adds `--pki DIR`. Any other
  argument makes it exit 2, with a message on stderr.
- **Each face listens on `127.0.0.1`, port 0.** The OS picks the port.
- **The announcement:** once every face is listening, one line on stdout, a flat JSON
  object. Nothing else ever goes to stdout.

  ```
  {"node":"v24.18.0","pid":12345,"http":"127.0.0.1:40001","raw":"127.0.0.1:40002"}
  ```

  - `node` is `process.version`, and `pid` is `process.pid`.
  - Each face's value is `ADDRESS:PORT`, both read back from `server.address()` once it
    listens, never from what was asked for.
  - The keys come in this order, with no others. Slice 2 adds its faces after `raw`.
- **It exits 0 when its stdin closes,** after closing every listener and destroying every
  open socket. It writes nothing to stderr unless it fails.
- **Its stdin closes once every process holding it has gone.** That means its suite, and
  any probe or command the suite was running: Chez's `system` children inherit the pipe's
  write end. So a suite that dies mid-probe leaves the origin serving until that probe
  ends, within `wire-probe-deadline` (30 s by default), or `bounded`'s 10 s. Measured: 19.3
  s after a SIGKILL during an idle-bounded probe.
- **A client that misbehaves never stops it.** Resets, half-closes, garbage, and a client
  vanishing mid-script each end that connection only. The raw face allows half-open
  connections, so a client that half-closes after its request still gets its whole
  script.
- **Any other error goes to stderr and exits 1.** `call-with-origin` holds every origin to a
  clean stop (§6), so a suite sees the origin die rather than pass without it.

## 4. The plaintext scenarios (slice 1)

### The well-formed face, `http`

It is built on `node:http`. Every response is deterministic: no `Date` (`sendDate = false`),
and headers written in a fixed order. A request carrying `Connection: close` gets
`Connection: close` back.

| Request | Response |
|---|---|
| `GET /status/CODE`, CODE 200–599 | status CODE, body `status CODE\n` |
| `GET /redirect/CODE?to=TARGET`, CODE 300–308 | status CODE, `Location:` the decoded TARGET, body `redirect CODE\n` where the status allows one |
| `GET /chunked` | `Transfer-Encoding: chunked`, three writes, `alpha\n`, `beta\n` and `gamma\n`, each its own chunk |
| `ANY /echo` | status 200, body: the request line as Node parsed it, then each header from `rawHeaders` in order, as `Name: value`, then a blank line, then the request body. Each line ends `\n` |
| anything else | 404, body `not found\n` |

What Node puts on the wire for each is measured, and the suite holds those bytes. Node
20.10.0 and 24.18.0 write the same bytes for every one. 204 and 304 carry no body and no
`Content-Length`, and 205 carries `Content-Length: 0`.

### The raw face, `raw`

It is built on `node:net`. Per connection it reads the request head, up to the first
`\r\n\r\n`, and gives up on one longer than 64 KiB. It takes the target from the request line,
`/raw/NAME` with an optional `?QUERY`, and plays NAME's script. Then it closes, so there is no
keep-alive.

- **A script is a list of steps:** write these bytes, wait N ms, end (FIN), reset (RST), or
  stall (write nothing until the client goes).
- **An unknown NAME or parameter, or one out of range, gets a fixed 400**, then the
  connection closes.

| Group | NAME | What it plays |
|---|---|---|
| framing | `content-length` | `HTTP/1.1 200 OK`, `Content-Length: 6`, `hello\n`, FIN |
| | `chunked` | `Transfer-Encoding: chunked`, chunks `hello` and `\n`, the last chunk, FIN |
| | `chunked-extensions-trailers` | chunk extensions, an upper-case hex size, a trailer section |
| | `chunked-tiny` | `hello\n` in one-byte chunks |
| | `close-delimited` | `Connection: close`, no length, `hello\n`, FIN |
| | `http10` | `HTTP/1.0 200 OK`, no length, `hello\n`, FIN |
| drips | `drip?bytes=N&gap=MS` | a head with `Content-Length: N`, then N bytes, one every MS ms. N 1–4096, MS 1–5000 |
| | `stall-after-head` | a head with `Content-Length: 6`, then stall |
| | `stall-before-head` | reads the request, then stall |
| oversized | `big-header?bytes=N` | one header, `X-Big:` and N bytes of `a`. N 1–1048576 |
| | `many-headers?count=N` | N headers, `X-H-1: v` to `X-H-N: v`. N 1–100000 |
| protocol errors | `bad-status-line` | `HTP/1.1 200 OK` |
| | `bad-status-code` | `HTTP/1.1 2000 OK` |
| | `bad-chunk-size` | a chunk size of `zz` |
| | `short-body` | `Content-Length: 10`, 5 bytes, FIN |
| | `reset-mid-body` | `Content-Length: 10`, 5 bytes, RST |
| | `conflicting-content-length` | `Content-Length: 5` and `Content-Length: 6` |
| | `chunked-and-content-length` | both framings at once |
| | `header-no-colon` | a header line with no colon |
| | `nul-in-header` | a NUL inside a header value |
| | `close-before-response` | reads the request, then FIN with nothing written |
| | `http09` | `hello\n` with no status line, FIN |
| tolerated | `bare-lf` | `HTTP/1.1 200 OK`, every line ending `\n` alone |
| echo | `echo` | `HTTP/1.1 200 OK` with a `Content-Length`, and the request head's exact bytes as body |

The builder writes each script's bytes. The suite's copy is written separately from that.

Drips stay small in the suite, a few bytes at tens of milliseconds, because `test-origin`
runs in every `make test` and under the memory gate. (`check-test-fails` deletes the real
suites in its copy, so it never runs them.)

## 5. The probe

```
node tests/wire-probe.mjs [--reset | --half-close] [--deadline MS] HOST PORT HEX IDLE-MS
```

- It connects and sends HEX's bytes once. HEX is pairs of lower-case hex digits, or
  `@FILE`, a file holding them, for more bytes than one argument can carry.
- It prints Scheme data on stdout, one datum per line. Times are whole milliseconds since it
  started.
  - `(connected MS)`, taken before it sends a byte.
  - `(data OFFSET MS "HEX")`, one per chunk it reads. Chunk boundaries are not part of any
    contract.
  - `(end KIND MS)`, where KIND is `eof`, `reset`, `timeout` (IDLE-MS passed with no data)
    or `deadline` (the whole run reached `--deadline`, 30000 by default), or `error`
    followed by the error's code. On `timeout` and `deadline` it destroys the socket.
  - `(reset-sent MS)`, with `--reset`, in place of any end line. Once its bytes are with the
    kernel, it resets the connection with `resetAndDestroy()`. A `destroy()` reaches the
    peer as a FIN, never a reset (measured).
  - `(refused "CODE" MS)` when the connection fails.
- With `--half-close`, it ends its side once its bytes are with the kernel, and goes on
  reading. Otherwise it never half-closes.
- It exits 0 when it ran, and 2 on a usage error.
- Slice 2 adds `--tls SERVERNAME`: TLS with no verification. The probe never judges a
  certificate.

## 6. The helpers in `(curl-testing)`

Each export has a type signature and tests in `test-curl-testing`.

- **`call-with-origin : (Origin -> Any) -> Any`**
  - It runs `$NODE` on `origin-script` (a parameter, `tests/origin.mjs` by default) under a
    small `sh` runner, which records node's pid and, once node exits, its exit status. Chez
    has no `wait`. `NODE` comes from the environment, or defaults to `node`.
  - It reads the announcement within `origin-timeout` (a parameter, 5000 ms), and requires
    the announced pid to be the recorded one.
  - It answers `(PROC origin)`, then closes the origin's stdin. Once PROC returns, it
    requires all of these, within the bound:
    - stdout ends;
    - nothing is written after the announcement;
    - nothing is on stderr;
    - the exit status is 0.

    Every raise carries the stdout, stderr and status it saw.
  - When PROC raises, that raise goes on unchanged, and the origin is still stopped, or
    killed.
- **`origin-node`, `origin-pid` and `origin-face`** read the announcement. An unknown face
  raises.
- **`read-announcement : String -> (Listof (Pair String (U String Natural)))`**
  - It is strict: one flat JSON object, with string keys, and values that are strings or
    naturals.
  - It refuses escapes, nesting, duplicate keys and trailing text, by raising.
- **`read-within`** reads a port, bounded by a monotonic deadline that it checks before
  every read, and by size. Every wait on a pipe, in the helpers and the suites, uses it or
  such a deadline. `capture-command`'s `system` waits with no clock: each command it runs
  is bounded by its own deadline, or by `bounded`.
- **The probes.**
  - `wire-probe : Origin Symbol Bytevector Natural -> Probe` runs the probe against a face,
    with an idle bound.
  - `wire-probe-reset` and `wire-probe-half-close` do the same with `--reset` and
    `--half-close`.
  - `wire-probe-deadline` is a parameter: how long any probe may run in all.
  - Bytes beyond 16384 go through a temporary `@FILE`.
- **`parse-wire-probe : String -> Probe`** reads the probe's output strictly.
- **A Probe holds:** `probe-bytes`, all the bytes received; `probe-end`; `probe-arrivals`,
  each chunk as `(offset . ms)`; and `probe-connected`.

## 7. Lifecycle checks

- **Loopback only.**
  - Every face's announced address is `127.0.0.1`.
  - On Linux, each face also refuses a connection to `127.0.0.2:PORT`, so a face bound to
    any address fails even if it announces loopback. Elsewhere this test is skipped, since
    `127.0.0.2` isn't a loopback address there by default.
- **OS ports.** Two origins at once announce different ports, and both serve.
- **A clean stop.** After `call-with-origin` returns, every face refuses connections.
  Stand-ins that exit 1, write to stderr, flood stdout, or die after an answer each make it
  raise, by name.
- **Open connections are destroyed.** A probe still connected when PROC returns sees eof,
  and the call returns promptly.
- **It outlives its suite only by a bound.** A child Chez starts an origin and reports its
  ports, then is killed with SIGKILL while idle: within 5 s, every face refuses connections.
  Killed mid-probe instead, every face refuses within the probe's deadline.
- **Survives a bad client.** After a reset mid-request, a half-close, and a client that
  vanishes during a drip, the next probe is served.
- **No helper outlives its call:** not the probes, the watchdogs, the child Chez, nor the
  stand-ins.
- **Timing.** A drip's body byte i arrives at least (i+1)×gap after the probe connected. The
  last arrives at least half of (N−1)×gap after the first, and on the 25 ms row each body
  byte arrives alone.
- **Ranges.** Every parameter is served at both edges of its range, and refused just
  outside them.
- **The 64 KiB head limit,** from both sides.

## 8. TLS and HTTP/2 (slice 2)

Designed in outline here, and settled when slice 2 is briefed.

- **`tests/make-test-pki.sh DIR`** writes, with EC P-256 keys:
  - a run CA;
  - a good leaf for `localhost`, `127.0.0.1` and `::1`;
  - an expired leaf;
  - a wrong-host leaf, for `wrong-host.invalid` only;
  - a second CA that is never trusted, and a leaf it signs.
- **The script is portable as measured** (2026-10-18). One script, using `req`, `x509 -req`
  and `ca -startdate/-enddate` with a config file, gave the same results on OpenSSL 3.5.7 (the
  container), OpenSSL 3.0.13 (Docker `ubuntu:24.04`) and LibreSSL 3.3.6 (Docker
  `alpine:3.14`):
  - the good and wrong-host leaves verify;
  - the expired leaf fails with error 10.

  A self-signed leaf is error 18 on OpenSSL and 20 on LibreSSL. So "untrusted" is a leaf of
  the second CA. The Mac's `/usr/bin/openssl` itself is not measured.
- **Faces:** `https`, `https-expired`, `https-wrong-host`, `https-untrusted` and `raw-tls`.
  Also `h2`, HTTP/2 over TLS with ALPN, and `h2c`, prior knowledge on plaintext.
- **Checks:**
  - `openssl s_client` verify codes against the run CA;
  - ALPN `h2` on `h2`;
  - on `h2c`, the connection preface answered by a SETTINGS frame;
  - one GET round trip, with frames the suite builds.
- **Raw HTTP/2 frames that nghttp2 refuses to send wait until a test needs them** (M7).

## 9. The drift guard (ADR-0017)

- `tests/known-libcurls.sexp` lists the libcurls the suites have been recorded against. Each
  row has a label, `where`, and the five fields compared exactly: `version`, `version-num`,
  `features`, `ssl-version` and `host`.
- **`test-drift` passes only when `(loaded-libcurl)`'s five fields equal exactly one row's.**
  It fails on any other libcurl, and prints that library's row, ready to add.
- A malformed file, a duplicate row, or a row with a missing or extra field fails by name,
  never as a suite that dies unnamed.
- **Rows at slice 1:**
  - the Guix container;
  - Ubuntu 24.04's `libcurl4t64`, which CI's `main` and `memory` lanes load;
  - the 7.85.0 floor that `scripts/ci/build-curl.sh` builds.

  The last two are measured in Docker with `tests/libcurl-oracle.c`. The Mac has no row until
  its first run.
- **The floor build becomes deterministic.** `build-curl.sh` runs `./configure
  --with-openssl` and lets `configure` find whatever optional libraries the machine has. So
  the floor's feature word could differ between Docker and the runner. Every optional
  library becomes an explicit `--with-…` (its `-dev` package listed in
  `packaging/debian-prereqs.txt`) or `--without-…`/`--disable-…`. RTSP stays on:
  `test-variadic` needs it.

## 10. CI and the floors

- **`make test` needs Node.** `NODE ?= node`, exported, and `require-tools` names it.
- **CI's lanes:**
  - `main` and `memory` use the runner's Node (22);
  - `floor` installs Node at `packaging/floors.sexp`'s version, with `actions/setup-node`
    pinned to a full SHA, reading the version through `scripts/ci/floor.sh node`.
- **`check-floors` holds every `node-version:` in a workflow** to
  `${{ steps.ID.outputs.NAME }}`, matching the key in any case, quoted or not.
  - **It reads text, so it refuses what it cannot read.** Any line of a workflow file with
    one of these fails, unread:
    - a `\` after a `"`;
    - an explicit key, `?`;
    - an alias or anchor where a key goes;
    - a character beyond ASCII;
    - a tab.
  - **Its limit:** it holds the expression's form, not the step behind it.
  - The floor lane also checks at run time that `node --version` is the floor's major.
- **Node 20.10.0 now, in Docker, since CI has never run.** The origin's suite runs there
  under Node 20.10.0, with Chez built by `scripts/ci/build-chez.sh` (ADR-0005, amended).
