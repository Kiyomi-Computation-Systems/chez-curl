chez-curl

An HTTP client for Chez Scheme, built on libcurl.

It has two levels, and a program may use either, or both:

  • (http-client), the high level. A session, and a call per request: http-get, http-post and the rest. It follows redirects by its own rules, retries by a policy you give it, keeps cookies, and streams both ways.
  • (curl), the low level. A request is data. An engine runs it on a thread of its own and hands you a token, which gives you the response. (http-client) is built on it.

Ideas to keep in mind

  • A status is data. A 404 or a 503 is an answer, not an error. A call raises when it was refused, when its transfer failed, when an answer passed a limit you set, and when it met a redirect it will not follow (Errors).
  • One engine thread runs many requests. To make many at once you need no thread per request: a group, or many tokens, on your one thread.
  • What you pass is checked before it is sent, and a refusal names the field and the reason, never your password or your cookie.
  • Close what you open. A session, an engine and a cookie jar hold native objects: call-with-http-session closes its session for you.
  • libcurl's version shows through in a few places, each one listed.

The examples

examples/ holds eleven small programs to copy from. Each calls the test server, tests/origin.mjs, a Node program in this repository, so start it first, in a terminal of its own, and leave it running. It prints one line of addresses, a new port at each start: an example takes the one after "http":, not raw's or h2c's, which speak other protocols. Run an example from the repository's root, with its base URL: http://, that address, and no trailing /, since each example adds its own paths. json-api.sps alone needs jsonparse, a submodule (Headers and JSON), and runs as scheme --libdirs src:build/scheme-libs --program examples/json-api.sps URL.

node tests/origin.mjs        # first: prints {"node":...,"http":"127.0.0.1:PORT",...}; Ctrl-D ends it
scheme --libdirs src --program examples/quick-start.sps http://127.0.0.1:PORT
Example What it shows
quick-start.sps one http-get
form-and-params.sps params on a query, and a form as a body
json-api.sps headers on a session and a call, and a JSON API, with jsonparse; it alone needs make deps, and src:build/scheme-libs as its library path
multipart.sps a multipart body of a string, bytes and a file
session-retries.sps a session's defaults, a redirect, and a retry policy
stream-download.sps a response read from a port as it arrives
stream-upload.sps at the low level, a body put a piece at a time
group.sps http-parallel, and a request group
cookie-jar.sps at the low level, a cookie jar: kept, sent, read out, loaded
errors.sps a status as data; a timeout, a body too large and a refused request
engine-and-tokens.sps at the low level, an engine, tokens and a mailbox

make test runs every example twice against one test server, and holds each run's output to examples/expected/.
