# M2 plan: one blocking request, plaintext and TLS

- **Date:** 2026-10-19
- **Status:** draft. Slice 1 is settled (§4). Slices 2 and 3 are settled in design (§5, §6);
  each starts with the measurements it lists. Slice 2's measurements are in, and settled
  what §5.3 records (2026-10-23). Slice 3's are in, and settled what §6.2 records
  (2026-10-24).
- **Scope:** brief §8's M2, and what the decision records hand M2
- **Records:** [ADR-0001](decisions/0001-bind-libcurl-directly.md) ·
  [ADR-0008](decisions/0008-curl-url-only.md) (amended 2026-10-19) ·
  [ADR-0012](decisions/0012-engine-thread-owns-every-handle.md) ·
  [ADR-0013](decisions/0013-collect-safe-blocking-calls.md) ·
  [ADR-0014](decisions/0014-valgrind-memory-gate.md) ·
  [global-constraints](global-constraints.md)

M2 proves the binding end to end. One request runs on the calling thread through
`curl_easy_perform`, with the variadic setopt and getinfo bindings, libcurl's parsed headers,
and TLS. Nothing is asynchronous, so a failure can only be the binding's.

**M2 adds nothing public.** `(curl)`'s exports do not change. From M3 on, only an engine owns
a transfer handle (ADR-0012), and M4 builds the request and response records (brief §8). So
M2's request lives in `(curl private transfer)`, which M3's engine reuses. The first public
request is M4's.

**The Apple arm64 gate holds.** M2 binds no setopt or getinfo option until `make
check-variadic` has passed on the maintainer's Mac and ADR-0001 records it (decided
2026-10-17). Slice 1 binds neither, so it starts now. Slices 2 and 3 start after that run.
That run passed on 2026-10-23 (ADR-0001, amended), so slices 2 and 3 may start.

## 2. Measured before planning (2026-10-19)

Scratch programs under `build/verify/m2/measure/` (not kept), in the container (Chez 10.4.0,
libcurl 8.20.0 with GnuTLS 3.8.13, Node 24.18.0) unless named otherwise.

- **Chez's `string` foreign type:**
  - it hands C UTF-8, the same bytes as `utf-8`: `é` is 2 bytes, `λ` 2, U+1F600 4;
  - **it cuts a string at an embedded NUL without a word.** `strlen` saw `"a\x0;b"` as 1
    byte, under both types. A URL with a NUL in it would reach libcurl shortened;
  - `#f` reaches C as NULL.
- **A whole transfer works.** The probe bound:
  - `curl_easy_perform` `__collect_safe`;
  - a write callable, `__collect_safe` and locked with `lock-object`, whose `WRITEDATA` was
    an integer key;
  - every string option through foreign memory and the existing pointer binding.

  Against the origin, `/echo` came back byte for byte, with a UTF-8 `User-Agent` intact. A
  200-byte drip made 200 callbacks while a second thread ran 145,512 collections, and every
  byte arrived.
- **`lock-object` is visible to a test.** The same probe without it died 6 runs in 6: 5 with
  `invalid memory reference`, 1 with a core dump. With it, 6 in 6 passed.
- **Under the memory gate's Valgrind options, callbacks gave 0 errors.** No
  `--undef-value-errors=no` was needed: 0 errors, and nothing definitely lost. The one
  suppression used was Guix's.
  - **The busy collecting thread starved the drip:** it timed out (28) with 0 callbacks,
    while that thread collected 92,297 times. Valgrind runs one thread at a time, so a test
    that collects beside a transfer must pace itself.
  - That answers ADR-0014's question for this shape. Slice 2 measures it again with the
    real suite.
- **TLS, on two backends.** GnuTLS 8.20.0 through the probe, and OpenSSL 3.0.11 under
  Debian 12's libcurl 7.88.1 through a C program, gave the same answers on every face:
  - `CAINFO` the run CA: the good face 0 (status 200); expired, wrong-host and untrusted
    each 60, `CURLE_PEER_FAILED_VERIFICATION`;
  - `SSL_VERIFYPEER` and `SSL_VERIFYHOST` both 0: all four faces 0, status 200;
  - no `CAINFO`, so the system store: the good face 60. That is the control: a refusal
    alone proves nothing (M1 plan, §8.8);
  - the `h2` face: HTTP/2 (`CURLINFO_HTTP_VERSION` 3), by libcurl's default ALPN;
  - `CAINFO_BLOB` also worked on GnuTLS 8.20.0.
- **URL verdicts vary by version.** 51 of 58 cases agree across 7.85.0, 7.88.1, 8.5.0 and
  8.20.0, and 7 do not. The maintainer chose shared answers plus version rows (ADR-0008,
  amended 2026-10-19).
- **From curl's documentation at the floor (7.85.0):**
  - `curl_url_set`: the caller "does not have to keep content around after a successful
    call";
  - setopt copies string options, except `CURLOPT_POSTFIELDS`, which the options API types
    as an object;
  - `curl_slist_append` "copies the string";
  - `CURLOPT_ERRORBUFFER` is kept until `curl_easy_cleanup`, and needs `CURL_ERROR_SIZE`
    bytes;
  - `CURLOPT_CURLU`'s handle is read during the transfer, never changed, so it must outlive
    `curl_easy_perform`;
  - `CURLOPT_MAXFILESIZE_LARGE` "has no effect" when the size is not known in advance;
  - `CURL_WRITEFUNC_ERROR` arrived in 7.87.0, after the floor. A write callback aborts by
    returning a count other than the one it was given, which is `CURLE_WRITE_ERROR` (23).

## 3. Decisions that bind every slice

### 3.1 Nothing native outlives the call that made it

- Every libcurl object and foreign block M2 makes is freed before the call that made it
  returns, raises or escapes. That covers easy handles, `CURLU` handles, slists, blocks, and
  strings for `curl_free`. Each is made and freed on one thread, under `dynamic-wind`.
- Re-entering a finished extent through a continuation raises, so nothing is used after it
  is freed.
- So M2 needs no guardians, and never hands a caller a handle.

### 3.2 The counters are a gate (ADR-0014, decision 7, amended)

- **`(curl private counters)` counts every native object** by kind: `block`, `easy`,
  `url`, `slist`, `curl-string` and `transfer`. Each count rises when the object is made,
  and falls when it is freed.
  - The counts are per process in M2, and per engine from M3.
  - They sit behind a mutex, since two threads may each run a blocking request.
  - It never loads libcurl, so any suite can import it.
  - **There is no reset.** A suite compares the counts before and after.
- **`suite-exit-status` fails any suite whose counts are not all zero at its end,** naming
  each count. Every suite goes through it already (`check-suites`). A suite that never
  touches libcurl has nothing to count.
- **The gate counts per process, so a child that reaches native reports its counts.** This
  plan first said the gate needed no new rule. Slice 1's review leaked a counted block on a
  refused load, in a child probe, and every suite passed. So every child a suite spawns that
  reaches native prints its counts, and the suite asserts them zero.
- **The plant:** a counted block, wrapped in an ftype pointer and dropped, as ADR-0014 asks.
  `check-test-fails` gains a suite whose tests all pass but which leaks that one block. It
  must exit 1, through the counters' message.
- `test-curl-testing` tests the new rule in `suite-exit-status`, and exits 1 on its own
  failures first ("a suite cannot vouch for the verdict it exits through").

### 3.3 Every string reaches libcurl through foreign memory

- **A string chez-curl hands libcurl is a NUL-terminated UTF-8 copy in a counted block,**
  made through the checked copy, passed as a pointer, and freed once libcurl is done. For
  setopt and `curl_url_set` that means as soon as the call returns. A string holding NUL is
  refused before anything is allocated.
- **Why:**
  - **No new variadic binding.** A string option goes through the existing
    `(uptr int uptr)` setopt, which `check-variadic` already plants. A `string`-typed setopt
    would be a fourth setopt binding, and it would need the Mac again.
  - **NUL can't be cut silently.** Chez's `string` type cuts at NUL (§2), so the refusal is
    explicit, in one place.
  - **The encoding is written down,** and the counters see every copy.
- **No new string crossing.** The two `string-not-kept` rows,
  `curl_easy_option_by_name` and `curl_easy_header`, keep their marks, since only
  chez-curl's own literals reach them. The only new crossing is the checked copy's.
- **Strings come back from libcurl as bytes:** `strlen`, then the checked copy into a
  bytevector. Whoever reads them decodes them. A URL is UTF-8. How a header's bytes become
  a string is slice 2's to settle, and every byte must survive.

### 3.4 The checked copy (ADR-0001, amended 2026-10-16)

- **`memcpy` is bound twice in `(curl private native)`,** once each way, and neither
  binding is exported. Their row in `tests/foreign-conventions.sls` gains
  `(bytevector-crossing ...)`, quoting ADR-0001: "One checked wrapper owns every copy
  between a bytevector and foreign memory."
- **What native exports instead:**
  - `copy-foreign->bytevector! ADDRESS BYTEVECTOR OFFSET N`;
  - `copy-bytevector->foreign! BYTEVECTOR OFFSET ADDRESS N`.

  Each raises an assertion violation, before calling C, unless:
  - OFFSET and N are exact non-negative integers;
  - `OFFSET + N` is at most the bytevector's length;
  - ADDRESS is a non-zero exact integer.

  N = 0 makes no call.
- **The foreign side is left to Valgrind.** Counted blocks are `malloc`'d, where Valgrind
  sees an overrun. A pointer libcurl hands chez-curl comes with its length.
- **Mutation-tested** (ADR-0001 asks for it): the bound dropped, `<` for `<=`, the offset
  left out of the sum, a check on one direction only. Each must fail by name.

### 3.5 One write callable, locked, keyed by an integer

Slice 2 builds it. The design is fixed now, so slice 1's seam rules fit it.

- **`write-body` is the one callable.** It is `(define write-body (foreign-callable
  __collect_safe ...))`, at `(curl private transfer)`'s top level: ADR-0013's decision 2.
  That fits the reader's rules as they stand ("a callable is the whole right-hand side of
  `(define name ...)`"). So M2 needs no reader change: no callable in a `let`, no factory,
  and no nested-pattern helper macro.
- **It is locked with `lock-object` where it is defined, and never unlocked.** It lives as
  long as the process. A behavioural test is the check, since §2 shows that a missing lock
  is visible.
- **`CURLOPT_WRITEDATA` carries an integer, the transfer's key.** The callable looks the key
  up in a table under a mutex, to find where the body goes. No Scheme object crosses into C.
- **It never raises into C.** Its body runs under a guard, which records anything raised
  against the key and returns 0. libcurl then answers 23, and the transfer raises what was
  recorded. The same path enforces the body limit.
- **Inside it, the copy out of libcurl's buffer is the checked copy,** a plain `memcpy`. The
  callable has reactivated the thread, so no collection can move the bytevector during the
  copy.

### 3.6 The seam's reviewed additions (ADR-0007)

Each is added by the slice that first uses it, with a test that watches the rule fire.

- **`allowed-chez-names` gains** `foreign-callable`, `foreign-callable-entry-point`,
  `lock-object`, `make-mutex` and `with-mutex` (slices 1–2), and `foreign-set!` if the
  getinfo slots need it.
- **`library-only-chez-names` gains:**
  - `foreign-alloc` and `foreign-free`: `(curl private memory)` alone. Native's one block
    today, the header probe's `hout`, moves to a counted block. Tests are exempt, so
    `test-variadic`'s own slots stay as they are.
  - `foreign-procedure`: `(curl private native)` alone. It is "the only library that calls
    into libcurl" today by its own comment; this makes that a check.
  - `foreign-callable`, `foreign-callable-entry-point` and `lock-object`:
    `(curl private transfer)` alone (slice 2).
- **`known-macros` gains `bind-blocking`,** a binder whose template carries
  `__collect_safe` (slice 2). `curl_easy_perform`'s row gains `(bound-by bind-blocking)`, so
  binding it any other way is `wrong-binder`, as the variadic rows are held.

### 3.7 What M2 raises

Both are `&curl-error`s, private until M4 makes the request public.

- **`&curl-url-error`:** the input, a reason, the `CURLUcode` or `#f`, and a message.
  - The reason is the code's name, from a table of the floor's 30 codes, 0 to 29 (7.85.0's
    `urlapi.h`). A later code has no name in the table and is reported by number.
  - chez-curl's own refusals have reasons of their own: a scheme that is not `http` or
    `https`, and a NUL in the input (ADR-0008, decisions 1 and 2).
- **`&curl-transfer-error` (slice 2):**
  - the `CURLcode` and `curl_easy_strerror`'s text;
  - the error buffer's text;
  - when the write callable aborted the transfer, what it recorded: the body limit, or
    what was raised.

  M4 maps the codes to conditions.
- **Each new constant is a row of `test-constants`.** That covers the `CURLcode`s a test
  names, the `CURLUcode` table, the `CURLINFO`s, `CURL_ERROR_SIZE` and the `CURLH_` origin
  bits. Every one must exist in the floor's headers, since the floor lane compiles against
  them.

## 4. Slice 1: the gate-free foundations (settled)

Branch `m2/foundations`. Nothing in it binds a setopt or getinfo option.

### 4.1 Records first

- `tls-mutation-log.md` says its scratch paths are not kept, as slice 1's log does.

### 4.2 The counters and counted blocks

- `(curl private counters)` and `(curl private memory)`, as §3.2 and §3.6 describe.
- `memory` exports `foreign-block` (`N -> Address`, counted, raising when `foreign-alloc`
  answers 0) and `free-foreign-block!`. Freeing an address that is not a live block raises
  rather than calling `foreign-free`. The table it keeps is what the counters count.
- Native's `curl_easy_init` and `curl_easy_cleanup` count `easy`, and the load's header probe
  goes through them, so the counts are zero once the load returns.
- `suite-exit-status` gains the counters' rule. `check-test-fails` gains the plant (§3.2).

### 4.3 The checked copies and C strings

- §3.4's two copies. Then two string helpers, built on the copies and on `strlen`, bound
  plain with a `cannot-block` row:
  - `call-with-c-string STRING PROC`: a counted UTF-8 copy with its NUL, handed to PROC as
    an address, and freed after PROC under `dynamic-wind`. A NUL in STRING is refused.
  - `c-string->bytevector ADDRESS`: the bytes up to the NUL, or `#f` for NULL.
- Native's `c-string`, which reads one byte at a time with `foreign-ref`, gives way to
  them.

### 4.4 The URL API (ADR-0008)

- **Native binds:** `curl_url`, `curl_url_set`, `curl_url_get`, `curl_url_cleanup`,
  `curl_url_strerror` (7.80.0) and `curl_free`. Each is required at load (`missing-api`),
  has a `cannot-block` row, and is counted.
- **`(curl private url)` exports:**
  - `url-normalize STRING`: what `curl_url_get` gives back for STRING;
  - `url-resolve BASE REFERENCE`: REFERENCE resolved against BASE (decision 4);
  - `call-with-parsed-url STRING PROC`: the `CURLU` handle, for slice 2's
    `CURLOPT_CURLU`, freed after PROC;
  - `require-http-scheme ADDRESS`: the scheme check on a parsed handle (decision 2).

  Each `curl_url_get` string is copied, then freed with `curl_free`. Each refusal raises
  `&curl-url-error`.
- **`tests/test-url.sps`** holds ADR-0008's 16 cases and RFC 3986 §5.4's 42. The build added
  12 non-ASCII cases, since every URL had been ASCII, which made 70 (ADR-0008, amended
  2026-10-23).
  - The 51 that every recorded libcurl agrees on are shared answers (60 with the new cases).
  - The 7 that vary are rows of `tests/known-url-verdicts.sexp`, keyed by `version`, for
    7.85.0, 8.5.0 and 8.20.0 (10 with the new cases).
  - A libcurl with no row fails, printing the row it would need, as `test-drift` does.
  - Every answer is asserted whole: the URL, or the refusal's code. No message is compared.
  - The scheme check refuses `file:///etc/passwd` after it parses.
  - A NUL in a URL is refused before libcurl sees it. Without the refusal, libcurl would see
    `http://a/` for `"http://a/\x0;b"`, so the test asserts the refusal, not just a failure.
  - The counts return to zero after every case, including the refusals.

### 4.5 The checks carried into M2 (ADR-0001, amended 2026-10-17)

- **A prototype check.** `test-constants` already compiles a program against the headers.
  It gains a prototype per bound entry point: the C return and parameter types as the header
  declares them.
  - The program assigns each entry point to a function pointer of that type. Compiled with
    `-Werror=incompatible-pointer-types`, it fails on a prototype that disagrees with the
    header.
  - The suite then holds each binding's Chez types to its prototype, through one fixed map:
    - a pointer to `uptr`, `void*` or `(* FTYPE)`, and to `u8*` only on the copy's row;
    - an `int` or an enum to `int`;
    - `unsigned int` to `unsigned-int`, `long` to `long`, `size_t` to `size_t`;
    - `curl_off_t` to `integer-64`.
  - The bindings' types come from `foreign-conventions`' scan, which already reads them.
  - A variadic prototype ends in `...`. Each of its bindings' value types must fit the
    `CURLOT` types it serves:
    - `long` for long and values;
    - `integer-64` for off_t;
    - a pointer for the rest.

    getinfo's destination must be a pointer. Typed `int`, it passed `test-variadic` (ADR-0001).
- **`curlot-types` is complete.** The suite reads the `CURLOT_` names from the preprocessed
  `curl/options.h`, through `$CC -E`, and requires `curlot-types` to name exactly those.
- **A complete layout's size is checked.** A layout row says whether its ftype is the whole
  struct. If it is, `sizeof` must equal `ftype-sizeof`: `curl-easyoption` now, and
  `curl-header` in slice 2. `curl-version-info-data` stays a prefix.

## 5. Slice 2: the blocking request, plaintext (after the Mac run)

### 5.1 First, measure

- **Each plaintext scenario's `CURLcode`, on the four libcurls:** 7.85.0, 8.5.0 (OpenSSL
  and GnuTLS) and 8.20.0. Where they vary, the suite takes ADR-0008's shape: shared answers
  and version rows.
- **How header bytes come back.** `nul-in-header`, `big-header` past
  `CURL_MAX_HTTP_HEADER` and `header-no-colon` against `curl_easy_nextheader`. That settles
  how a header becomes a string, with every byte kept (§3.3).
- **A collecting thread paced so the gate's Valgrind still lets a transfer run,** and still
  catches a missing lock in the container.

### 5.1.1 Measured, 2026-10-23

The measurements went through C (`build/verify/m2s2/measure/`, not kept) on four libcurls:
- 7.85.0, the floor build;
- 8.5.0 with OpenSSL and with GnuTLS, Ubuntu 24.04's;
- 8.20.0, the container's.

The first three ran in Docker `ubuntu:24.04` with Node 20.10.0, and 8.20.0 ran in the
container with Node 24.18.0.

- **The plaintext scenarios.** 8.5.0's two backends gave the same answer to every scenario.
  Every scenario but these five gave the same answer on all four. They are eight cases, since
  `big-header` at 1,048,576 bytes answers as it does at 102,400, and `MAXFILESIZE_LARGE`
  alone was measured against three bodies:

  | Scenario | 7.85.0 | 8.5.0 | 8.20.0 |
  |---|---|---|---|
  | `big-header?bytes=102400`, past `CURL_MAX_HTTP_HEADER` | 27 | 27 | 100 |
  | `many-headers?count=100000` | 0 | 56, after 22,735 headers | 100, after 5,000 |
  | `bad-status-code`, `HTTP/1.1 2000 OK` | 1 | 1 | 0, status 200 |
  | `conflicting-content-length` | 0, both headers kept | 0 | 8 |
  | `MAXFILESIZE_LARGE` alone, with no length | 0, no effect | 63 | 63 |

  The rest included:
  - `stall-after-head` and `stall-before-head` under `TIMEOUT_MS`: 28;
  - `reset-mid-body`, `reset-after-pause` and `bad-chunk-size`: 56;
  - `short-body`: 18;
  - `close-before-response`: 52;
  - `bad-status-line` and `http09`: 1;
  - `nul-in-header` and `header-no-colon`: 8;
  - a write callback that refuses: 23;
  - `MAXFILESIZE_LARGE` below a `Content-Length`: 63 before any body;
  - `http10`: version 1 and no headers.

  `CURLE_TOO_LARGE` (100) arrived in 8.6.0, after the floor, so it is no constant. The rows
  write codes as numbers.
- **Header bytes.** `curl_easy_nextheader` never hands back a NUL. Every other byte inside a
  value reaches the caller as sent, on all four: a value holding every byte from 0x01 to 0xFF
  but CR and LF came back whole. Leading and trailing SP and HTAB are trimmed. Names keep their case, and a repeated name keeps each value, in order, with
  `amount` and `index`. Folding, an empty value and a CR inside a value vary by version
  (ADR-0001, amended 2026-10-23).
- **The body limit.** On 8.5.0 and 8.20.0, `MAXFILESIZE_LARGE` with no length known cuts the
  body at the limit, then answers 63. So a callable's own check never sees a byte past the
  limit, and only 7.85.0 would show it.

  With `MAXFILESIZE_LARGE` at the limit plus one, all four libcurls gave the same answers in
  20 cases:
  - a `Content-Length` beyond the limit plus one is refused before any body, 63;
  - otherwise the callable sees the first byte past the limit and refuses it, 23;
  - a body of exactly the limit completes.
- **The lock test.** The test pairs a drip with a collecting thread that sleeps 2 ms between
  collections.
  - Natively, the callable with `lock-object` passed 4 runs of 4, and without it failed 4 of 4.
  - Under the gate's Valgrind options, it passed 4 of 4 with the lock, and failed 4 of 4
    without, at 2 ms and at 20 ms pacing. Each failure was an exception from Chez, then a
    definitely-lost easy handle.

  At 2 ms the transfer ran to the end, with 155 to 203 collections beside it.

### 5.2 What it builds

- **Bindings:**
  - `curl_easy_perform`, through `bind-blocking`;
  - `curl_easy_strerror`, with a `string` result, which Chez copies;
  - `curl_easy_nextheader` (7.83.0);
  - `curl_slist_append` and `curl_slist_free_all`.

  Each has a row in the conventions table and a prototype row, and `curl-header` joins the
  layouts as a complete struct.
- **`write-body` is held to `curl_write_callback`'s prototype,** with the same
  `_Static_assert(_Generic(...))` form slice 1's prototype check uses. That check skips
  callables today.
- **Option ids come from the loaded library, by name, once per process** (ADR-0001,
  decision 2).
  - A name it does not know raises, naming it.
  - Setting an option checks the value against its `CURLOT` type, picks the binding by that
    type, and asserts the code it returns. A test holds each `CURLOT` type to its binding:
    long and values to `long`, off_t to `integer-64`, and the rest to the pointer one. Slice 1
    holds each binding only to the list its variadic row allows.
- **The private request.** Its fields:

  | Field | Option |
  |---|---|
  | URL | parsed by `call-with-parsed-url`, then `CURLOPT_CURLU` |
  | method, `get` or `head` | `NOBODY` for `head` |
  | headers, a list of name and value | `HTTPHEADER`, an slist freed after the transfer. CR, LF and NUL are refused |
  | user agent, or `#f` | `USERAGENT` |
  | timeout in milliseconds | `TIMEOUT_MS` |
  | body limit in bytes | enforced by the callable, and also `MAXFILESIZE_LARGE` |

  The transfer always sets `PROTOCOLS_STR` and `REDIR_PROTOCOLS_STR` to `http,https`,
  `NOSIGNAL` to 1, the write callable and its key, and `ERRORBUFFER`, a counted block. It
  follows no redirect: that is M5's policy.
- **The response:** the status (`RESPONSE_CODE`), the HTTP version (`HTTP_VERSION`), the
  effective URL (`EFFECTIVE_URL`, copied), every header of the last request (`nextheader`,
  `CURLH_HEADER`, request -1), and the body.
- **ADR-0001's first FFI test, at last:** each of the three setopt bindings, observed in a
  real transfer.
  - **A string:** `USERAGENT`, byte for byte in `/echo`'s answer.
  - **A long:** `TIMEOUT_MS` against `stall-after-head` gives 28 within its bound. `NOBODY`
    gives no body.
  - **An `off_t`:** `MAXFILESIZE_LARGE` below a `Content-Length` gives 63.

  Each fails by name on Apple arm64 if its binding loses the annotation, so the Mac reruns
  `check-variadic` with these tests in place.
- **The suite, `test-transfer`:**
  - every plaintext scenario of M1's §4, asserted whole: status, headers, body or code;
  - the body limit, through the callable;
  - a raise inside the callable, re-raised by the transfer;
  - two threads, each with its own transfer, at once;
  - the lock test, with a paced collecting thread beside a drip;
  - the counts back to zero after each case.

  It runs under the memory gate.

### 5.3 Settled at the start of slice 2 (2026-10-23)

- **Header strings are Latin-1, both ways.** The maintainer chose it (ADR-0001, amended
  2026-10-23).
  - A response header's name and value become strings, one char per byte.
  - A request header's name and value, and the user agent, reach libcurl as counted Latin-1
    copies, through a Latin-1 twin of `call-with-c-string` in native.
  - The origin gains a raw script, `header-bytes`, whose one header holds every byte from 0x01
    to 0xFF but CR and LF.
- **`MAXFILESIZE_LARGE` is the body limit plus one** (§5.1.1). So the callable enforces the
  limit on every libcurl, and a declared length well past it is still refused before its body.
- **`curl_easy_strerror` returns `uptr`, read as bytes,** as `curl_url_strerror` is. §5.2 said
  a `string` result. The rule in global-constraints, that strings libcurl hands back are read
  as bytes, wins.
- **A header name must be a token** (RFC 9110, §5.6.2). §5.2 refused only CR, LF and NUL. A
  name holding `:` or a space would send a different header from the one asked for.
- **The request's refusals are `&curl-request-error`:** the field, the value and a reason:
  - `embedded-nul`, `line-break` (CR or LF) or `not-latin-1`, whichever char comes first;
  - `not-a-token`, for a name.

  The request's constructor raises them, before anything native. A value of the wrong type
  is an assertion violation.
- **`&curl-transfer-error` has a reason:**
  - `perform-failed`: `curl_easy_perform` answered a code, and the callable recorded nothing;
  - `body-limit` and `callback-raised`: the callable recorded one of those;
  - `setopt-failed`: a setopt answered a code, naming its option;
  - `unknown-option`: the loaded libcurl does not know an option's name;
  - `no-handle`: `curl_easy_init` answered NULL.
- **The raise test reaches the callable through the request's `chunk-hook`,** a private
  field. When it is set, it is handed a copy of each chunk, inside the callable. M2 has no
  other caller code.
- **The version rows are `tests/known-transfer-verdicts.sexp`,** keyed by version, as
  `known-url-verdicts.sexp` is.

### 5.4 Settled in review (2026-10-23)

Three reviews, each followed by a fix round, settled these. ADR-0001, ADR-0007, ADR-0008,
ADR-0009 and ADR-0013 are amended with them, and global-constraints holds the rules.

- **A request is checked again at perform time, on a private snapshot,** and the snapshot is
  what is sent. Strings and pairs are mutable, and a `string-set!` after the check put
  `X-Injected: yes` on the wire. The C-string helpers, URL checking and option names copy
  first too.
- **The request reasons gain three:** `surrounding-whitespace`, since libcurl drops a blank
  value with its own header of that name; `duplicates-field`, a second Host or a User-Agent
  beside the field; and `framing-header`, `Content-Length` or `Transfer-Encoding`, which a GET
  would send and a server would wait on. An empty user agent is an assertion violation.
- **The test seam, `perform-transfer-with`, follows ADR-0009, narrowed.** The maintainer chose
  that over removing it: long, enumerated-value and `off_t` options only, and a by-id
  deny-list with twins. So the three "`MAXFILESIZE_LARGE` alone" version rows went: five cases
  vary by version now.
- **The pins are `pinned-options`,** set first on the handle, with their names only as data.
- **Escapes from the callable** (ADR-0013, amended 2026-10-23):
  - the test hook's continuations are turned into raises;
  - each native object is made, or freed, in one critical section with its record, and every
    mutex is held through `locked`;
  - a critical section around `curl_easy_perform` was measured and reversed: it deferred
    collections and Ctrl-C until the transfer ended. The maintainer chose to allow an escape
    from perform, and count it. chez-curl never touches that handle again;
  - the escapes run in a child process, `tests/transfer-escapes.sps`.
- **`check-variadic` runs `test-transfer` on each mutant.** On the Mac the order is:
  `make test`, then add the 8.7.1 rows `test-transfer` prints, then `make check-variadic`.
- **Ambient proxy variables** fail `test-transfer` first, by name. chez-curl's proxy policy is
  M4's.

## 6. Slice 3: TLS (after slice 2)

- **The request gains two fields:**
  - a CA file, or `#f` for the system store. It becomes `CAINFO`, the string option the Mac
    watches;
  - whether to verify. `#f` sets `SSL_VERIFYPEER` and `SSL_VERIFYHOST` to 0: the brief's
    escape hatch for verification.
- **`test-transfer-tls`,** with a fresh PKI from `make-test-pki`. On each backend:
  - **the control:** the good face with the run CA, 200;
  - expired, wrong-host and untrusted with the run CA, each 60;
  - all four with verification off, 200;
  - the good face with the system store, 60;
  - the `h2` face: HTTP/2 when the libcurl has the `http2` feature. Every recorded row has
    it.
- **The backends:**
  - GnuTLS: the container's 8.20.0, and Ubuntu's 8.5.0 through `CHEZ_CURL_LIBCURL`;
  - OpenSSL: Ubuntu's 8.5.0, and the floor;
  - SecureTransport: Apple's 8.7.1, on the Mac. Whether it honours `CAINFO` for a run CA,
    rather than only the keychain, is shown first there (brief §9, risk 3). A refusal there
    is a finding. This said it was settled before slice 3 merges. The Mac was out of reach
    when slice 3 was ready, and the maintainer chose on 2026-10-24 to merge first. So the
    Mac's run is owed before M2 is done (§7), and a finding there gets its own branch.
- **CI gains the GnuTLS lane** that brief §9 risk 3 names. It loads Ubuntu's
  `libcurl-gnutls.so.4` through `CHEZ_CURL_LIBCURL`, against `libcurl4-openssl-dev`'s

  until CI does.

### 6.1 Measured, 2026-10-24

The measurements went through C (`build/verify/m2s3/measure/`, not kept) on the four Linux
libcurls slice 2 measured. 7.85.0 and Ubuntu's two 8.5.0 builds ran in Docker
`ubuntu:24.04`, with and without `ca-certificates`, and 8.20.0 ran in the container
([ADR-0018](decisions/0018-ca-file-is-the-only-anchor.md) has the detail).

- **§6's verdicts agree on all four** wherever a system store exists, so `test-transfer-tls`
  needs shared answers alone, and no rows file yet. With no store installed, the OpenSSL
  builds answer the system-store control 77, not 60.
- **The other cases, alike on all four:**
  - a missing CA file, and a directory given as one: 77;
  - a CA file whose path holds `é` and `λ`: 200;
  - `SSL_VERIFYPEER` off alone still checks the host, and `SSL_VERIFYHOST` off alone the chain.

  An empty CA file answers 60 on GnuTLS and 77 on OpenSSL, so no test uses it.
- **Ubuntu's libcurl trusts its default `CAPATH` beside `CAINFO`.** Clearing `CAPATH` makes
  the CA file exclusive.
- **Beside a CA file, `CAINFO_BLOB` and `SSL_OPTIONS`' `NATIVE_CA` widen trust.**
- **Guix's libcurl 8.20.0 writes `SSL_CERT_FILE` and `SSL_CERT_DIR` over `CAINFO` and
  `CAPATH`** when a transfer starts. Its 8.6.0, an older patch, let the request's settings win.
  The host's profile exports both; the container passes neither.
- **The `https` face answers HTTP/1.1 and `h2` HTTP/2** on all four, by ALPN.
  `curl_easy_nextheader` gives an HTTP/2 response's headers lower case, as sent, with no
  `:status`: `/status/200` gives `content-length` alone. The builder measured that on 8.20.0,
  and `test-transfer-tls`, which asserts it whole, then passed on 7.85.0 and on Ubuntu's
  8.5.0 with OpenSSL and with GnuTLS, in Docker.

### 6.2 Settled at the start of slice 3 (2026-10-24)

The maintainer chose each of these (ADR-0018; ADR-0009, amended 2026-10-24):

- **A CA file is the only trust anchor.** The field sets `CAINFO` and clears `CAPATH`, and
  `CURLE_NOT_BUILT_IN` from `CAPATH` is accepted, since that backend has no CA directory.
  `#f` sets neither.
- **Every transfer sets verification:** `SSL_VERIFYPEER` and `SSL_VERIFYHOST` at 1 and 2, or
  both 0 when the request turns it off.
- **`CAINFO_BLOB` and `SSL_OPTIONS` are the CA file's twins,** refused by the test seam.
- **Guix's environment override is pinned and deferred.** `test-transfer-tls` fails first when
  `SSL_CERT_FILE` or `SSL_CERT_DIR` is set, and a child test pins the override by world and
  version. Its policy is M4's.
- **The TLS settings are data.** The transfer computes the four settings from the request,
  and applies exactly those. `test-transfer-tls` holds them whole, since no lane's system
  store can show `CAPATH` left set.
