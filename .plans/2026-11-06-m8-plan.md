After M8 a caller can:

- send a `multipart/form-data` body of fields and files, at both levels (ADR-0039);
- count on every response's headers being capped alike, the floor's included (ADR-0040);
- read user docs: a short README.org, Markdown pages and a reference of every export;
- take chez-curl at the `v0.1.0` tag.

- **The low level keeps its stand,** no policy (brief §6.1): a multipart body is a value of the
  request's `body` key; the high level carries it through a call, and owns what is policy.
- **Caller code never runs on the engine's thread** (ADR-0012). The mime handle is made and freed
  there, with its transfer.
- **Not in M8** (ADR-0038): streamed, nested or encoded parts, a part's own headers; a key for the
  cap; a docs site; making the repository public, Akku, a release archive's exclusions.
- **M8 has five slices:** the memory job in two; the header cap; multipart; the docs; the release.

## 3. Decisions that bind every slice

### 3.1 The public surface

**The low level.** A request's `body` takes a fourth kind, beside a bytevector, `stream` and `#f`:

```scheme
(multipart PART ...)
;; PART:   (NAME SOURCE OPTION ...)
;; NAME:   a string
;; SOURCE: a string, sent as UTF-8; a bytevector; or (file PATH), PATH a string
;; OPTION: filename STRING | type STRING, each at most once, in any order
```

For example, the URL positional as today:

```scheme
(make-curl-request "https://example.com/upload" 'method 'post
  'body '(multipart ("title" "Holiday")
                    ("photo" (file "photos/beach.jpg") type "image/jpeg")
                    ("notes" #vu8(104 105) filename "notes.txt")))
```

- **A wrong shape is an assertion violation,** its irritant named by kind (`shown-value`), never
  printed; a broken rule on a well-shaped body is a named refusal (§3.7). `(multipart)` is well
  shaped, and refused, `multipart-empty`.
- **What is copied, and when.** The list and its metadata, each name, filename, type and path, are
  copied, checked, and the copy used, when the request is made and again at submit, as
  `credentials` is. A part's data, a string or a bytevector, is copied at submit alone, as a
  bytevector body is today (ADR-0023, decision 4): a request built inside the high level's
  critical sections then costs no copy of the data. A test mutates each metadata string after
  construction and submits.
- **A file part's path is resolved once** (ADR-0039, amended): when the request is made, a relative
  path is resolved against `(current-directory)`, and the path checked by `stat` alone, a regular
  file; submit checks it by `stat` again, without resolving; nothing is opened on the caller's side.
  An empty path, or one holding U+0000, is `part-file`.
- **A multipart body is a whole body:** `post`, `put`, `patch` and `delete` take one; `get` and
  `head` refuse it (`body-not-allowed`), and `body-length` beside it is refused
  (`body-length-without-stream`), each by today's rule.
- **A file part's filename defaults to its path's last component,** libcurl's own default, and the
  filename rules check it, so a path whose last component holds `"` needs a `filename` of its own.
- **A part's type defaults to libcurl's** (mime-wire, question 6, alike on the five lanes): from the
  filename's extension; for a file part, then from the path's; then `application/octet-stream` for a
  file part. A data part with no filename, or a filename whose extension libcurl does not know, gets
  none. The docs list the extensions libcurl knows.
- **`curl-request-body`** answers the list the request holds, as it answers a bytevector body's
  today, uncopied; submit checks it again.

**The high level.** A call takes a `multipart` key, the parts alone, as `form` takes its pairs:

```scheme
(http-post s "https://example.com/upload"
  'multipart '(("title" "Holiday") ("photo" (file "photos/beach.jpg") type "image/jpeg")))
```

- `multipart` beside `body` or `form` is refused, `multipart-beside-body`; `body` beside `form`
  keeps `body-and-form`. `multipart` with `get` or `head` is `body-not-allowed`, its field
  `multipart`, as `form`'s is `form`.
- **The call resolves each relative path once,** when it starts, so its retries and redirect hops
  send the files it named, whatever `chdir` comes between.
- A multipart call adds no `Content-Type` header. A session's `Content-Type` header is dropped from
  a multipart call, as a call's `user-agent` drops the session's `User-Agent` header; a call's own
  is refused by the low level (§3.4).
- **A multipart body is not a stream** (ADR-0039, consequences): a group takes one, a retry resends
  it, and a redirect that keeps a body keeps it, each hop a fresh transfer with its own mime.

  MEMORY_SHARD=1`, the other `MEMORY_SHARD=2`. `check-memory-gate.sh`'s own nested runs unset
  `MEMORY_SHARD`.
- **The split is balanced by measurement:** each suite's time under the gate, from the logs of
  `main`'s last push run and PR #47's last run, the slower, kept in the slice's research. Each shard
  aims at no more than 16 minutes on a pull request's runner.
- **The branch's required checks** take the two new jobs' names: the maintainer's setting, which the
  slice names and does not read.

### 3.3 The header cap (slice 2; ADR-0040, amended)

- **Every transfer sets `HEADERFUNCTION`.** A streamed response's callable counts as it reads the
  head, as today; a buffered transfer's counts alone. Its counts span the transfer: header lines,
  a head's status line and empty line left out, and every byte handed.
- **Past 1,000 lines or 102,400 bytes it records `header-limit` and answers a short count,** and
  refuses every later call too, as every callable does once a reason is recorded. The recorded
  reason wins over libcurl's code (`finish-transfer`, today's rule), so 8.5.0's lost trailer
  refusal fails too. `header-limit` is a reason of `&curl-too-large`, as `body-limit` is.
- **libcurl's own earlier refusals keep their codes** (ADR-0040, decision 4, amended), held in
  `test-headers`' per-version table (§3.8), and listed in the docs.
- **The values are constants in `transfer.sls`,** each written out in `test-headers`, with no key.
- **Two of test-transfer's cases meet the cap on every lane:** the 50,000-header case at its 1,001st
  line, and the shared `big-header?bytes=102380` case, whose one line and status line pass 102,400
  bytes. The slice rewrites both as cap tests. libcurl's own count and byte caps lie past
  chez-curl's, so no suite reaches them any more; the caps probe's research keeps them.
- **`SUPPRESS_CONNECT_HEADERS`,** the hatch's today, hides a `CONNECT` answer from the callable while
  8.20.0 and 8.23.0 still count it: the slice measures it and decides whether it becomes a twin.
- **The origin's HTTP/2 faces raise Node's send limits,** as the caps stand-in did, and every h2
  suite is run with them before the routes are added.

### 3.4 Multipart (slice 3; ADR-0039, amended)

- **The load probes mime** (decision 4, made exact), after `curl_global_init`, where the header
  probe runs: `curl_formadd` with `CURLFORM_COPYNAME`, `CURLFORM_COPYCONTENTS` and `CURLFORM_END`,
  then `curl_formfree`; and `curl_mime_init` with NULL, then `curl_mime_free`. Both run in one
  critical section, through the raw bindings inside `native.sls`, never counted, so nothing they
  make outlives the section. Mime is there only when `curl_formadd` answers 0 and `curl_mime_init`
  a mime: 7.85.0 built without it answers `curl_mime_init` with a working mime. A 7 or a NULL means
  it is not; any other answer is recorded by name, and counts as not. The answer is kept as
  data beside `libcurl-info`, never in `native.sls`'s failed-load path. A libcurl without mime
  keeps every other request; a multipart body is refused at submit, `multipart-unsupported`.
- **The owner registry:** the mime is recorded with its thread, as kind `mime`, in its counting
  section. One procedure of `native.sls` adds a whole part, its name, data or file, filename and
  type, to a mime whose owner it checks, so no part's address leaves `native.sls`. Each new
  procedure joins `test-native`'s wrong-thread table.
- **The engine checks each file part before the transfer's setup,** on its thread and outside any
  critical section: `stat`, a regular file, then an open and a close (ADR-0039, amended). A failure
  fails the transfer before it starts, `part-file`.
- **The engine makes the mime in `start-transfer!`,** after `curl_easy_init`, so it belongs to its
  own easy handle, as 7.85.0 requires (mime-files, table 7): `curl_mime_init` on that handle, then
  each part through the one procedure: data from a counted foreign copy, as `COPYPOSTFIELDS`' bytes
  are, or `curl_mime_filedata`, bound blocking with a counted foreign copy of the path, since it
  `stat`s. Any answer but 0, or a NULL, fails the transfer before it starts, `part-file` for a
  file's, `mime-failed` for the rest.
- **The body's options:** `sends-body?` takes a multipart `delete`, so its `Expect:` blank goes out;
  `method-settings` sets the method's options, `CUSTOMREQUEST` for `put`, `patch` and `delete`, and
  then `MIMEPOST`, the transfer's last body option (the `UPLOAD` trap), in place of
  `POSTFIELDSIZE_LARGE` and `COPYPOSTFIELDS`. `MIMEPOST` moves from the twins to the body field's
  options, as a field takes over a twin (ADR-0009, amended 2026-10-31).
- **A multipart transfer leaves `Content-Type:` out of its blanks,** and keeps `Expect:`. A
  caller's `Content-Type` header beside it is refused, `multipart-content-type`.
- **The mime is a counted kind,** `mime`, made and freed in one critical section with its count
  and its record, freed by `free-transfer!` after `curl_easy_cleanup`, the precedent order. An
  abandoned easy handle keeps its mime, as it keeps its jar hold. Parts are the mime's, not
  counted. `test-transfer`'s nesting check gains its setter and both places in its lists.
- **`MIME_OPTIONS` becomes owned,** and is never set (decision 2). `EXPECT_100_TIMEOUT_MS` stays
  the hatch's: with the `Expect:` blank, it waits on nothing unless a caller asks for `Expect`.
- **The byte rules:** a name, filename and type refuse every character U+0000 to U+001F and
  U+007F, and a name and filename refuse `"`: `part-bytes`. A name, filename or type is never
  empty: `part-empty`. Each names the part by its index and field, never its value.
- **No part's secret is printed:** `test-multipart` builds a body holding one secret in a value, a
  name, a filename, a type and a path, raises every refusal of §3.7 and every shape's assertion
  violation with it, `part-file` from submit and from the engine, and `mime-failed` by a seam, prints
  each condition, the request, the token and its outcome, and asserts the secret absent from every
  text (AGENTS.md's printing traps).
- **The engine's reasons** `part-file` and `mime-failed` are reasons of `&curl-transfer-error`, in
  `curl-transfer-error-reasons`, with a request size of 0, as `setopt-failed` is.
- **The request size's documentation** (`conditions.sls`, and ADR-0022) says that for a multipart
  body on 7.85.0 and 8.5.0 it holds the head alone.

### 3.7 Refusals

Each has a reason symbol of its own, raised where today's rules raise: a request's own shape at
construction and again at submit, and what needs the loaded libcurl, the file system or the engine
at submit or in the transfer. A wrong type is an assertion violation.

| Slice | Condition | Reasons |
|---|---|---|
| 2 | `&curl-too-large` | `header-limit` |
| 3 | `&curl-request-error` | `part-bytes`, `part-empty`, `multipart-empty`, `multipart-content-type`, `part-file` (made and submitted), `multipart-unsupported` (at submit) |
| 3 | `&curl-transfer-error` | `part-file` (the engine's check, or `curl_mime_filedata`'s answer), `mime-failed` |
| 3 | `&http-request-error` | `multipart-beside-body`; `body-not-allowed` with the field `multipart` |

`test-conditions` and `test-request` write the reasons and keys out, and grow with them. Each
refusal is tested beside a neighbour that passes, on bytes where they differ: each control
character and `"` at each place, beside the bytes next to them that pass.

### 3.8 What varies by version, and what is documented

Each is a per-version table in its suite, a row for each of the five Linux libcurls and 8.7.1,
taken from two runs, a missing row failing by name (ADR-0017). A cell that races holds every
answer seen.

- **slice 2,** libcurl's refusals that come before any line reaches the callable (ADR-0040,
  amended): a line of 102,400 bytes (27 on 7.85.0 and 8.5.0, 100 on 8.20.0 and 8.23.0 over
  HTTP/1.1; over HTTP/2, 27, 16 or 56, or 52, 56 and 16 for a line HPACK cannot Huffman-code);

  trailers (the same); a 5,000-byte trailer line over HTTP/1.1 (56 on 7.85.0 and 8.5.0, 100 on 8.20.0
  and 8.23.0); more than 5,000 HTTP/2 trailers on 8.23.0 (56); 7.85.0's HTTP/2 trailers among a
  response's headers. And the cap's own refusal, alike on every lane where a line arrives.
- **slice 3:** `CURLINFO_REQUEST_SIZE` (the head alone on 7.85.0 and 8.5.0, head and body on 8.20.0
  and 8.23.0, 0 on 8.7.x by an earlier trap); a file changed after the engine's check, each change
  made once the origin holds the head, so the cell does not race: grown, a malformed body answered

### 3.9 The seam and the conventions

- Each new binding gets a prototype row and a conventions row. `curl_mime_name`, `curl_mime_type`
  and `curl_mime_filename` take strings libcurl copies (`string-not-kept`); `curl_mime_data` takes a
  counted foreign copy, never a bytevector; `curl_mime_filedata` is bound blocking, `__collect_safe`,
  with a counted foreign copy of its path, since it `stat`s, and on 7.85.0 and 8.5.0 `access`es.
- **`curl_formadd` is the seventh variadic use.** `check-variadic.sh` and `test-collect-safe` count
  seven; `test-variadic` gains a row that reaches it, a valid form answering 0 and an unknown
  option 4; on Apple arm64 the use's mutant must fail that row, and `test-library-loading`'s decoy
  logs the options it was handed. `make check-variadic` is due on the Mac with slice 3 (§9).
- **The decoy** (`tests/decoy-libcurl.c`) gains `curl_formadd` and `curl_mime_init`, answering 0 and a
  mime by default, and switches that make them answer 7 and NULL, as `DECOY_OPTIONS_OFF` and

## 11. The plan's own decisions, open to review

1. **A file part's filename defaults to its path's last component,** checked by the filename rules.
2. **A session's `Content-Type` header is dropped from a multipart call;** a call's own is refused.
3. **An empty part list is refused,** `multipart-empty`: libcurl sends a closing delimiter alone,
   a body no form needs.
4. **A high-level call resolves its relative paths once,** when it starts, and a low-level request
   when it is made (ADR-0039, amended, decided by the maintainer; where at the high level is the
   plan's).
5. **No CI job builds a libcurl without mime:** the decoy's switches hold the probe's no in every
   run, and a Docker run of the two builds holds it once, its log kept.
6. **Each memory shard runs the planted defects,** at 84 s more for the second.
7. **The cap's values are constants,** not a configuration: `header-limit` names the cap, and the
   docs say its values.
8. **A part's data is copied at submit alone,** its metadata when the request is made and at submit.
9. **The engine's `part-file` and `mime-failed` are transfer errors,** as `setopt-failed` is.
